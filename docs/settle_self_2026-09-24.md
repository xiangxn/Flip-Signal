# 结算自算：推送优先的三层回退（2026-09-24，flip / tail 共用）

**一句话**：官方结算的 `openPrice`/`closePrice` 实测**就是边界 N 与 N+300 那两秒的 TWAP 推送值**
（逐位相等），所以结算判定可以自算——两条边界推送在手即闭市 **+10s** 定案；推送缺失的窗口
才在闭市 **+45s** 后取官方接口（避开未收敛的临时值）；官方也失败才交回 gamma（UMA）轮询。
三层来源逐行落 `settle_src` 可事后审计。

**性质**：**结算口径的等价改写**（不是新估计量，也不是 P&L 杠杆）。实证依据是「官方值 == 边界推送」
逐位相等（Q1/Q2/Q3 共 852 次比较 0 例外），故自算与官方**在定义上同值**；真正变化的只有
「多久知道结果」与「依赖几个外部服务」。

---

## 1. 为什么改

用户提问（原话）：

> 看看 `twap_adapter.go` 的推送价格，官方结算的价格是对齐的 5 分钟开始的一条还是前一个窗口的
> 最后一秒（即 59 秒）。如果刚才新窗口的 open 等于前一个窗口的 close，那就可以直接用推送的
> 价格数据来结算，只有当获取推送价格失败（可能因为网络丢了）才去拉取官方的结算价格。

探针证据（`python/v4/19_boundary_price_probe.py --no-fetch --win-dir data/v4live`，
样本 = 837 个实盘窗，2026-09-20T17:00 → 2026-09-23T16:00；官方缓存覆盖其中 315 窗）：

| # | 比较 | n | 结果 |
|---|------|---|------|
| Q1 | 官方 `open(N)` vs 边界那一秒的推送 `anchor(N)` | 315 | **315/315 逐位相等** |
| Q2 | 官方 `close(N)` vs 下一个边界的推送 `anchor(N+1)` ★核心 | 309 | **309/309 逐位相等** |
| Q3 | 官方 `close(N)` vs 官方 `open(N+1)`（用户假设，官方口径） | 228 | **228/228 逐位相等** |
| Q4 | 官方 `close(N)` vs 引擎现口径 `close_stream(N)`（到达口径） | 315 | 0% 逐位相等，\|差\| p50 **1.234 美元**（0.02σ）、p90 3.669 美元（0.07σ）、max 11.89 美元 |
| Q0 | 对照：官方 `close(N)` vs `anchor(N)`（错位窗，必不等的验证） | 315 | 0% 逐位相等，\|差\| p50 **51.83 美元 = 1.00σ**、p90 2.94σ、max 523.30 美元 |
| Q5 | **现口径**自算方向 vs 官方方向 | 315 | **3 个不一致（0.95%）** |
| Q6 | 官方 API 方向 vs 市场实际结算方向（gamma） | 113 | **113/113 一致** |

σ 尺子 = 本批窗口中位振幅 **6.023 bps = 51.83 美元/窗**（n=315）；bps 分母取该窗 `(open+close)/2`。

三条读数：

1. **Q0 的对照是这套证据的地基**：错位一格的差异是 **1.00σ = 51.83 美元**，而正位是 **0 差异**。
   「对齐到窗口第 0 秒」不是近似成立，而是**定义级相同**——官方取的就是边界那一秒的推送。
2. **Q5 的 3 个错误恰好是切换动机**：三例官方 Δ 分别是 −0.0786 / −1.0900 / −0.0795 美元
   （窗口振幅中位 51.83 美元 ⇒ 都是**万分之一量级的贴线窗**），而引擎的**到达口径** close 在这
   三窗漂到了零的另一侧。改用精确推送后（Q2 语义），这三窗的判定与官方**逐位同源** ⇒ 误差归零。
3. **Q6 说明「官方 API 方向 == 市场结算方向」**：官方接口与 gamma/UMA 的口径一致，
   故三层回退之间**不存在判定分歧**，换层只改时延不改编号。

### 缺失面（决定回退频率的是这个，不是精度）

`winstats_*` 全量实盘统计：**854 个窗**里 `anchor_exact=true` **839（98.24%）**，
拿不到精确推送的 **15 个（1.76%）**——且这 15 窗**全部 `ticks=298`**（整窗 tick 齐全 ⇒
采集链路活着，是上游那一秒没发/推送丢了，不是我们掉线）。

⚠️ 一次结算要**两条**边界推送（N 与 N+300），**两边界缺一即走官方层**：

```
预计走官方层的结算比例 ≈ 2×1.76% − 1.76%² ≈ 3.5%
```

（这是从单边界缺失率推的组合上界表达，非实测——纸面跑起来后按 `settle_src` 分布复核。）

## 2. 改了什么

新增 `internal/settle`（**零外部依赖、零 SDK、不 import `internal/flip`**），
另有 `internal/feed/official_pair.go` 提供 SDK 侧的取数闭包：

| 位置 | 内容 |
|------|------|
| `internal/settle/settle.go` | `Outcome(open, close)`（`close > open` ⇒ Up，与回测/gamma 同号）；`Anchors`（按 `event_start` 存边界推送，`OutcomeFor` 需**两条**边界全在）；`Resolver`（三层回退状态机） |
| `internal/settle/settle_test.go` | 判定词表钉在 `flip.OutcomeUp/OutcomeDown` 上（本包不 import flip，用**常量相等断言**替代依赖）；三层的时点/次数/幂等/剪枝/Nil 回调 |
| `internal/feed/official_pair.go` | `NewPricePairFetcher` 返回 `PricePairFetcher`——**一次调用同时取 open 与 close**（官方接口本就一并返回，不拆两次请求） |
| `internal/flip/types.go`、`internal/tail/types.go` | `Record.SettleSrc`（`json:"settle_src,omitempty"`） |
| 两族 `recorder.go` | `Resolve(conditionID, outcome, at, src)` 多一个 `src` 参数并落到行上 |
| `cmd/flip/main.go`、`cmd/tail/main.go` | 起 `Resolver`；gamma 注册点**全部收敛**到 `GiveUp`；锚通道在收到推送时**无条件** `anchors.Put(边界秒, price)` |

### 三层与时点

```
闭市 ──+10s──▶ ① 推送自算   两条边界推送在手 ⇒ 立即定案（src=push）      ← 实测覆盖 ~96.5%
      ──+45s──▶ ② 官方接口   闭市+45s 起每 5s 一次、至多 6 次（至 +70s）  ← 覆盖推送缺失的窗口
      ──+75s──▶ ③ gamma 轮询 交回 trading.ResolutionPoller（src=gamma）  ← 官方也失败才兜底
```

- **① 为什么是 +10s**：闭市时唯一还在等的是 close 那条推送（边界 N+300，闭市那一刻才发布；
  open 那条在窗口开局就已入 `Anchors`）——实盘 880 个命中窗口里它的本地到达延迟只有
  **1s(771 窗) / 2s(94 窗)** 两档，**没有一窗晚于 2s**，10s = 5 倍实测上界。
  ⚠️ 决策 #15 记的「最晚 +12.1s」是**取锚通道 500ms 轮询下**的观测上界（发布延迟 + 轮询相位），
  不是推送本身的到达延迟，不能当等待期依据——首版 25s 正是照抄了取锚通道的 20s 预算，
  代价是每条信号白等 15s（2026-09-24 用户实测「结算仍要 40-50s」后下调，见 §6）。
  常量 `defaultPushWait`。
- **② 为什么必须等 +45s**：官方接口在闭市后头几十秒返回的是**未收敛的临时值**
  （+40s 才收敛，见决策 #14 与 `docs/dog020_anchor_upgrade_2026-09-18.md` §9）——早取等于用一个
  比要修的问题更大的误差去结算。常量 `defaultOfficialWait` + `defaultMaxTries=6`。
- **③ gamma 保留为最后一层**：不是冗余——`UmaResolutionStatus=="resolved"` 是**市场结算本身**，
  前两层都拿不到时它是唯一权威（如官方接口 429/维护、推送长时间断流）。
- **每层的重试点只在下一 tick 试探**：`tick()` 由 `Run()` 每 5s 驱动一次，无睡眠、无每行 goroutine。

### 触发点收敛（顺带修掉一个竞态类）

原先有**三处**往 gamma 预先 `Register`（信号落盘时、挂单定稿时、重启恢复时）。现在**一处都没有**
——所有注册只发生在 `GiveUp`。理由：同一行被两个驱动抢会有一边报「结算回填未命中」；
而 `Pending()` 直接扫 `Recorder.PendingSignals()`（`isSettlable` 已过滤掉
`unfilled/rejected/submitting/resting`），**重启恢复**因此免费复用同一条路径，无需单独分支。

## 3. 可见性

| 字段 | 位置 | 取值 |
|------|------|------|
| `settle_src` | `touches_*` / `tail_*` 每行 | `push` \| `official` \| `gamma`；**空 = 本字段引入前的旧行**（`omitempty`） |

消费方式：按 `settle_src` 分桶对账「自算是否与官方一致」——`push` 桶里的任何一行若事后被证实
与官方不符，就是这套前提被推翻的**直接证据**（不需要重跑全量）。

## 5. 未做 / 已知

- **三个时点是代码常量，不进配置**（`defaultPushWait` 10s / `defaultOfficialWait` 45s /
  `defaultMaxTries` 6，可经 `settle.Options` 覆盖但 `cmd/*` 不传）：45s 是「官方值已收敛」
  的**正确性下限**，做成配置键只会招来「调小一点更快出结果」——那正是决策 #14 要避免的
  拿未收敛临时值结算。与扫尾盘「参数全部不可调」同一条理由。
- **σ 的 close 口径未改**：`hist_bps` 仍取窗末 `lastTick.TwapPrice`（**到达**口径），与本次
  改的**结算** close（精确推送）不是同一个数——两者相差 p50 1.234 美元（Q4）。这是既有不对称
  （open 早已是评估口径、close 是到达口径），**本次有意不动**：动它会改 `σ` ⇒ 改浅洞带判定 ⇒
  不是结算口径问题而是策略参数问题，得单独走一轮回测。
- **`Anchors` 不做淘汰**：进程内按窗口累积（576 条/日），量级数 MB/年，不值得加淘汰逻辑；
  进程重启即清空（重启后老窗口的结算自动落到官方层/ gamma——两条都是权威路径）。
- **官方层的时延代价**：推送缺失的窗口结算要等到 **+45s**（而 gamma 是闭市后数分钟），
  比主路径慢 ~30s——这是「不拿未收敛临时值换 30s」的有意取舍。
- **日亏熔断的反应时点提前**：`DailyPnl` 的输入从「等 UMA 结算」变成「闭市 +10s」，
  代价是熔断可能在**极少数贴线窗**（Q5 那类万分之一量级）上先于 gamma 生效——
  由于自算与官方**逐位同源**，这不构成判定分歧，只是同一结论早几分钟到达。
- **`Fetch` 为 `nil` 时的行为**：跳过官方层直接 `GiveUp`（由 `TestResolverNoOfficialLayer` 钉住），
  不是「永远 continue」——早期实现有这个 bug，已修。

## 6. 2026-09-24 追加：推送层等待期 25s → 10s

用户反馈：**上线自结算后「目前看还是需要 40-50s 多才能结算」**。实测取样（实盘 v4live/v4-tail，
2026-09-23 18:03 部署后的样本）拆出四个来源：

| # | 来源 | 实测量级 | 本次处理 |
|---|------|---------|---------|
| a | **推送层白等 25s** | 主路径 push 行实测 **26~27s** | ✅ 本次修（10s） |
| b | 官方层（上游那一秒没发） | 18:20 窗 **61s**、tail 一窗 67s | 不动（+45s 是收敛点，决策 #14） |
| c | 进程重启清空 `Anchors` | tail 17:25 重启后一窗 **339s**（落到 gamma） | 不动（见 §5 末，属已知取舍） |
| d | 前端 15s 列表刷新粒度 | 26s 的结算在页面上显示成 26~41s | 不动（展示口径，非结算口径） |

**为什么能砍**：闭市时唯一还在等的是 close 那条推送（边界 N+300，闭市那一刻才发布；open 那条
在窗口开局 ~2s 内已入 `Anchors`）。实盘 **880 个命中窗口**的该条推送本地到达延迟只有两档：

| 到达延迟 | 窗数 |
|---------|------|
| 1s | 771 |
| 2s | 94 |
| ≥3s | **0** |

即 10s = 5 倍实测上界；配合 5s 扫描粒度，推送层定案落在 **闭市 +10~15s**。
**不是 P&L 杠杆**：只改「多久知道结果」，不改任何判定（`Outcome` 与 `settle_src` 的取值都不变）；
未命中的窗口仍在 +45s 走官方层（它的门槛是 `defaultOfficialWait`，与 `PushWait` 无关）。
验收：`TestResolverPushTier` 改钉 +9s 不动 / +10s 定案，`go test ./internal/... -race` 全绿。
