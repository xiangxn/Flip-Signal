# 策略总结：Polymarket BTC 5分钟市场的 TWAP 预测反转策略

### 一、市场与目标
- 交易 Polymarket 的 **BTC 5分钟** UP/DOWN 市场。
- 结算依据是最终 60 秒的 TWAP（相对开盘价 Open 的涨跌）。
- 核心 edge：当市场一侧价格被打到很低（≤0.3）时，用 Binance 实时数据精确预测最终 TWAP，判断是否已经具备穿越 Open 的条件。

### 二、入场观察条件
当 **UP 或 DOWN 任一侧价格 ≤ 0.3** 时，开始密切观察（原来说的 0.25 也可，0.3 更宽松一点）。

### 三、核心计算（统一离散公式）
实时计算最终结算 TWAP 的预测值：

$$
TWAP_{pred}
=
\frac{1}{60}
\left(
\sum_{k=\max(R-59,\ 1)}^{R} \hat{P}_k
+
\sum_{k=R-59}^{\min(0,\ R)} P_k
\right)
$$

- $R$：距离结算剩余秒数
- 已知部分用真实 Binance 历史价格
- 未来部分用预测路径 $\hat{P}_k$

**第一版预测路径**（线性）：
\[
\hat{P}_k = P_0 + v \cdot k
\]
其中 $v$ 是当前估计的速度。

### 四、交易信号
计算：
\[
D_{pred} = TWAP_{pred} - Open
\]

- 如果 $D_{pred} > +M$（M 为安全边际），且 **UP 价格 ≤ 0.3** → **买入 UP**
- 如果 $D_{pred} < -M$，且 **DOWN 价格 ≤ 0.3** → **买入 DOWN**

（M 可根据剩余时间、波动率动态调整，是后续优化重点）

### 五、辅助过滤（提高胜率）
单纯的速度还不够，需要用以下信号提高对未来路径的信心：
- Binance 出现**反向大单**（与当前 TWAP 方向相反的大额成交）
- 订单流（Order Flow）持续同向
- 盘口失衡（Orderbook Imbalance）
- 短期加速度、波动率等

这些主要用于：
1. 确认当前 $v$ 的方向和持续性
2. 决定是否提高/降低安全边际 M
3. 未来可直接升级 $\hat{P}_k$ 的生成方式

### 六、策略逻辑一句话
> 当市场把一侧打到 ≤0.3 时，不再简单看“有没有反向大单”，而是用精确的 TWAP 滚动公式判断：**当前的速度 + 历史价格滚出效应，是否已经足够让最终 TWAP 穿越 Open**。只有预测显示有明显穿越，且有订单流支持时，才买入便宜的一侧。

### 七、当前版本定位
- **第一版**：只用线性速度 + 历史滚出效应（可立即回测）
- **后续升级**：把大单、订单流、盘口等因素融入未来价格路径 $\hat{P}_k$，让预测更准

### 八、**TWAP-pred 离散公式**

$$
\boxed{
TWAP_{pred}
=
\frac{1}{60}
\left(
\sum_{k=\max(R-59,\ 1)}^{R} \hat{P}_k
+
\sum_{k=R-59}^{\min(0,\ R)} P_k
\right)
}
$$

### 说明

- 最终结算窗口始终是时间点 $ R-59,\ R-58,\ \dots,\ R $（共 60 个点）。
- 其中 $ k \le 0 $ 的点用已知真实价格 $ P_k $。
- 其中 $ k \ge 1 $ 的点用预测价格 $ \hat{P}_k $。
- 当某个求和的下限 > 上限时，该求和视为 0（自动处理空集）。

### 两种情况自动覆盖

**1. $ R \ge 60 $**（例如 $ R=180 $）  
- 已知部分求和为空  
- 只剩未来部分：$\displaystyle\sum_{k=R-59}^{R} \hat{P}_k$

**2. $ R < 60 $**（例如 $ R=30 $）  
- 已知部分：$\displaystyle\sum_{k=R-59}^{0} P_k$
- 未来部分：$\displaystyle\sum_{k=1}^{R} \hat{P}_k$

### 线性速度假设下的具体形式

若采用最简单的线性预测：

$$
\hat{P}_k = P_0 + v \cdot k \quad (k \ge 1)
$$

则可进一步写成：

- **当 $ R \le 59 $**：

$$
TWAP_{pred}
=
\frac{1}{60}
\left(
\sum_{k=R-59}^{0} P_k
+
\sum_{k=1}^{R} (P_0 + v k)
\right)
=
\frac{1}{60}
\left(
\sum_{k=R-59}^{0} P_k
+
R P_0 + v \frac{R(R+1)}{2}
\right)
$$

- **当 $ R \ge 60 $**：

$$
TWAP_{pred}
=
\frac{1}{60}
\sum_{k=R-59}^{R} (P_0 + v k)
=
P_0 + v \left( R - 29.5 \right)
$$

### 实现（伪代码）

```python
def predict_twap(R, P_history, P0, v):
    # P_history: 字典或数组，包含 k <= 0 的真实价格
    known_sum = 0.0
    future_sum = 0.0
    
    start = R - 59
    for k in range(start, R + 1):
        if k <= 0:
            known_sum += P_history[k]
        else:
            future_sum += P0 + v * k   # 线性假设，可替换成更复杂模型
    
    return (known_sum + future_sum) / 60
```

### 九、后续
- 最终窗口永远是 $[R-59,\ R]$ 这 60 个点（离散）或 $[R-60,\ R]$（连续）
- 落在过去的部分 → 直接用真实历史价格
- 落在未来的部分 → 用预测价格

所以公式能算出什么样的 $TWAP_{pred}$，**真正起决定性作用的就是你对未来价格路径 $\hat{P}_k$（或 $\hat{B}(t)$）的假设**。

### 目前的层次

1. **第一版（最简单）**  
   未来路径 = 线性：  
   $$
   \hat{P}_k = P_0 + v \cdot k
   $$
   只由当前速度 $v$ 决定。

2. **后续可升级的方向**（也就是文章里提到的那些）  
   让 $\hat{P}_k$ 变得更真实，例如：
   - 加入加速度（匀加速）
   - 速度随时间衰减
   - 根据 order flow / 盘口失衡 / 大单 动态调整瞬时速度
   - 加入波动率（变成带随机性的路径，或取期望）
   - 直接用短期预测模型输出整条路径

统一公式就像一个「框架」，  
**未来价格路径才是这个框架里唯一需要认真建模的核心变量**。

你把未来路径预测得越准，$TWAP_{pred}$ 就越有价值。

### 可以直接支持的回测内容

1. **第一版核心公式**（线性速度 + 离散统一公式）  
   - 用 `ticks` 重建价格历史 → 计算 known sum / $ H_{exit} $  
   - 用最近几秒 `bin.price` 估算 $ v $  
   - 实时算 $ TWAP_{pred} $ 并与 `twap_open_price` 比较

2. **入场条件过滤**  
   - 当 `yes_ask ≤ 0.3` 或 `no_ask ≤ 0.3` 时开始观察  
   - 结合速度方向 + 预测穿越幅度 $ D_{pred} $

3. **大单/订单流增强**  
   - 检测突然放大的 `buy_vol` 或 `sell_vol`（反向大单）  
   - 计算短期订单流失衡  
   - 用盘口量比做确认

4. **完整闭环验证**  
   - 预测是否穿越 → 实际 `outcome` / `twap_close_price` 是否一致  
   - 统计不同剩余时间、不同 margin、不同速度强度下的胜率

### 需要注意的小问题

- 时间戳不是绝对完美的 1 秒间隔（偶尔有跳动），代码里要用实际 `ts` 差值计算速度，而不是假设严格 1 秒。
- `twap.age_ms` 可以用来判断当前 TWAP 是否新鲜。
- 早期 `rem` 从 298 开始，说明数据采集几乎覆盖了整个 5 分钟。
- `trades` 数组是 Polymarket 侧的成交汇总，对分析市场反应有用，但对 TWAP 预测本身不是必须。
