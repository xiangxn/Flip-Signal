## §0 预注册判据（先写死，再跑）

### 0.1 共同纪律

1. **训练/评估一律按日 OOF**（GroupKFold on `date`）——同一天内部高度相关（同 regime、
   同行情），随机切分等于偷看。**绝不在训练行上评估**。
2. **一律日级重采样**：单臂用日级 bootstrap，改动用**日级配对 Δ**（同一天两版策略的
   P&L 差，按日重采样 2000 次）;逐笔指标（AUC/Brier）同样按日重采样。
3. **置换必须按日整块打乱标签**（日内顺序保持）。按行打乱会把零分布算窄——审计实测：
   光是「扫阈值 + 挑最好」就能刷出 +3.6U 的假提升。
4. **检出力**：14 天 2074 单、45 输单 ⇒ **最小可检出 Δ ≈ ±9.8U**（2U/注）。
   小于这个量级的真实增益本轮**测不出来**（要 ~56 天）；不得事后放宽门槛。
5. 标签 = **官方最终 outcome**（不用中途价格变化，与 gbm.md 第 164 行一致）。
6. §0 自检三关（`00_selfcheck.py` / `01_build_dataset.py` / `lib_sim.py`）：
   oracle pin `6704 / 2074 / 97.830280% / +70.314372U` 逐位复现 + 手工复算 + 无未来信息
   截断检验。任一不过 ⇒ 全部作废重来。

### 0.2 Track A（阈值动态化）判据

链结构、检查点位置一个不动，只把**四个常数阈值换成状态的函数**（预注册单轴网格，
不允许事后拼组合）：

| 轴 | 现行常数 | 动态形式 | 预注册网格 |
|---|---|---|---|
| walk 腿 | `walk ≥ 43$` | `walk ≥ χ·σ` | χ ∈ {0.5, 0.6, 0.7, 0.8, 0.9, 1.0} |
| dev 腿 | `dev ≥ 63$` | `dev ≥ ψ·σ` | ψ ∈ {0.8, 1.0, 1.2, 1.5, 2.0} |
| σ 腿 | `σ ≥ 40$` | `σ ≥ ς·σ_prev中位` | ς ∈ {0.5, 0.75, 1.0, 1.25} |
| 地板 | `fill > 0.83` | 按 σ 三分位阶梯 | {0.80, 0.83, 0.86}（带单调性约束） |

阈值函数在**训练折内拟合**（按日 GroupKFold），评估用折外行拼起来的 OOF 宇宙。

**四条全过才立项**：① OOF 的日级配对 Δ 95% **下界 > 0**；② 净 Δ ≥ **+10U / 14 天 @2U**；
③ **搜索校正置换**（把网格格数算进 p）**p < 0.05**；④ 分半（08-25 切点）两半同向。
任一不过 ⇒ 进「已否」登记，不做第三版。

### 0.3 Track B（GBM 直接下单）判据

**主规则（预注册）**：tick 级 GBM 预测 `P(热门侧赢)`；逐秒扫描 `rem ≤ 150`，
**首个 `p̂ − fill > 0` 的 tick 下单**，整窗一单。只买热门侧（与现策略同族）。
训练时**按 1/窗内 tick 数加权**（有效样本 = 3640 窗, 否则 542439 个 tick 会假装成
542439 个独立样本）。

**四条全过才立项**：① 模拟 P&L 的日级配对 Δ（vs 现基线 +70.314372U）95% **下界 > 0**
且净 Δ ≥ **+10U / 14 天 @2U**；② 入场笔数 ≥ 现基线的 **50%**（防「只下 3 笔全赢」）；
③ 窗口级 OOF **AUC 的日级置换 p < 0.05**；④ 分半同向 + δ 扫描的搜索校正置换 p < 0.05。

**对照三件**（缺一不可）：① 现策略 +70.314372U；② **无模型退化版**（同一模拟器、
触发 = 固定价格门槛 `fill > x`）——证明「模型不是被一个常数门槛复现」；
③ **规则 + 模型过滤**（模型只在现行链的候选 tick 上行使否决权，不过则该段按
`walk_low` 的语义继续走链）——即 gbm.md 原本的「Rule Gate + GBM Filter」口径。

### 0.3B B2｜全窗模型：从 0s 起扫 + label = 官方 outcome

> ⚠️ 本节 2026-10-01 **追加**：写于 B1（§4）出结果**之后**、B2 任何一次运行**之前**。
> 触发 = 用户口径：「对于 gbm 给下单信号，应该从 0s 就开始丢给它，用最终的 outcome 来当
> 事件的 label」。

B1 把模型**限制得太死**：只扫最后 150s、只买热门侧、label 是「热门侧赢」。B2 放开三处：

1. **训练与扫描域 = 整窗**（`rem ∈ (0, 300]`；首个可判定 tick 通常 `rem ≈ 298`，
   即**窗口一开就喂**，与用户口径一致）；
2. **label = 官方 outcome**（`y = 1 ⟺ Up 赢`）——不再以「热门侧」为轴，模型输出
   `P(Up)`；
3. **双侧可下单**：同一时刻两侧各自比价——买 Up 付 `yes_ask`、买 Down 付 `no_ask`，
   哪边的「模型价 − 要价」大买哪边。

**主规则（预注册，V0）**：tick 级 GBM 预测 `P(Up)`，逐秒扫**整窗**，首个
`max(p̂ − yes_ask, (1 − p̂) − no_ask) > δ`（**δ = 0**）的 tick 下单，整窗一单，持到结算。
训练同样按 1/窗内 tick 数加权（有效样本 = 窗数）。**不加任何价格地板 / rem 限制 / 规则腿**
（一旦加了就成了 B1 的形态）。

**分解变体（预注册；用于归因，不是备用主规则）**：

| 变体 | 扫描域 | 可买侧 |
|---|---|---|
| **V0（主）** | 整窗 | 双侧 |
| V1 | 整窗 | 只买热门侧 |
| V2 | `rem ≤ 150` | 双侧 |
| V3 | `rem ≤ 150` | 只买热门侧（≈ B1 主规则，但模型换成「全窗训练 + Up 标签」） |

**四条全过才立项**（与 0.3 同式，基线同 `+70.314372U`）：① 日级配对 Δ 95% **下界 > 0**
且净 Δ ≥ **+10U / 14 天 @2U**；② 入场笔数 ≥ 基线 **50%**；③ tick 级 **与** 窗口级 OOF AUC
的日级整块置换 **p < 0.05**；④ 分半同向 + δ 扫描的**搜索校正**置换 p < 0.05。

**必报**（防止只报好看的形态）：入场 rem / fill / 侧别分布、按 rem 分桶 EV、
`(模型价 − 要价)` 分桶 EV、校准表、模型 vs 市价（去水基准 `yes_ask/(yes_ask+no_ask)`）的
Brier/logloss、**每笔够不够 CLOB 下限**（`stake=2U` 在 `fill < 0.4` 时买不到 5 股 ⇒ 实盘挂不出去）。

⚠️ **检出力那条不适用**：0.1 节「最小可检出 Δ ≈ ±9.8U」是按现策略的赔付结构（赢 +0.02U /
输 −2U）算的；B2 的成交价可以从 0.5 到 0.99（`fill=0.5` 时赢 +2U / 输 −2U）⇒ 每笔盈亏幅度
天然更大、区间更宽。判决一律看**区间与置换 p**，**不得**拿「点数为正」当依据。

**与已否家族的关系**：`docs/tail_entry_timing_2026-09-29.md` 否掉的是「把**规则链的检查点**
提前/推后」（换阈值/换检查点不算新机制）；B2 是**模型驱动的整窗扫描**——没有检查点、
没有阈值腿，不同类。但同一套稳健性要求照旧（按日 OOF、日级配对 Δ、日级整块置换、
分半、搜索校正）。

### 0.4 实盘一致性（非判决依据）

`data/tail-live` 8 天**不是干净前向**：规则版本三次改动（09-26 / 09-29 / 10-01）、
成交内生（GTC 挂单等成交 = 逆向选择）、价位段与回测不同。故**只作一致性检查**：
① 按现行规则重放的实盘行上，core 模型的判别力与校准方向；② 特征漂移表
（回测前半 / 后半 / 实盘 的分位 + PSI）；③ **成交率 × p̂ 十分位**（逆向选择证据）。
**实盘真实 P&L 不作判据**（成交率与 p̂ 负相关 ⇒ 拿它评模型是拿选择效应评模型）。

## §2 特征（14 个 tick 级 + 1 个信号级）

⚠️ 本节是**我对 gbm.md 那份清单的取舍**（用户要求：不照搬，按对本项目的理解定夺）。
gbm.md 共列 43 个特征；我把它们压到 **14 个**（tick 级），逐条交代去向。

### 2.1 留下并保留原义的（优先级最高的一组）

| 特征 | 定义 | 为什么留 |
|---|---|---|
| `fill` | 热门侧有效价（ask 优先 / bid 兜底） | **它就是盈亏平衡胜率本身**——模型的对手；唯一「不做任何事」的基准 |
| `rem` | 距闭市秒数 | 三段链的全部时间结构；连续量取代 `stage` |
| `sd_bps` | σ / anchor × 1e4 | σ 的**相对**形态（BTC 64k→84k，绝对美元不可跨期） |
| `dev_sigma` | `sgn·(spot − anchor) / σ` | 方向的核心量；σ 归一后跨价位可比（memory：63$ 在 64k 是 9.8bps、84k 是 7.5bps） |
| `walk_sigma` | `sgn·(twap − anchor) / σ` | **已写进结算线**的那部分位移（决策 #29 的闸就是它） |
| `basis_sigma` | `sgn·(spot − twap) / σ` | 还没写进账本的缺口；`dev = basis + walk` 恒等 |
| `book_latency_ms` | 盘口延迟 | gbm.md 把它当数据质量量——我同意留着（同时是行情状态的代理） |

### 2.2 我自己加的（gbm.md 没有）

| 特征 | 定义 | 加入理由 |
|---|---|---|
| `slack_sigma` | **冻结假设下的预计结算 dev** / σ（`rem ≤ 60` 才与 `dev_sigma` 分家） | 问题不是「现在差多远」而是「**结算时**差多远」：结算线是 TWAP-60，`rem ≤ 60` 后已定局的那段压着结果。这是 `internal/tail/curve.go:RequiredPrice` 的同一量——**把规则里已有的市场结构量喂给模型**，而不是让它从 `rem × dev` 自己拼 |

## §3 Track A 结果（阈值动态化）—— ❌ 不立项

`03_track_a_threshold.py`：四个轴、单轴预注册网格，阈值在**按日 GroupKFold 的训练折内
拟合**（每折在训练日上选 P&L 最好的那一格），评估 = 折外行拼起来的 OOF。
基线 = +70.314372U / 2074 单（§0 自检逐位复现）。

| 轴 | OOF 网格 | 折内选出的最优 | OOF Δ vs 基线 | 日级配对 95% | 分半 Δ（h1/h2） | 搜校 p | 判据 |
|---|---|---|---|---|---|---|---|
| `walk ≥ χ·σ` | χ ∈ {0.5…1.0} | **5 折全选 χ=0.8** | **+5.76U** | **[−9.89, +21.55]** | +11.69 / **−5.92** | 0.0249 | ❌ ①下界<0 ②<+10U ④分半反向 |
| `dev ≥ ψ·σ` | ψ ∈ {0.8…2.0} | ψ=0.8（1 折 1.0） | −14.66U | [−41.86, +9.70] | −14.79 / +0.13 | 0.6160 | ❌ |
| `σ ≥ ς·σ_prev中位` | ς ∈ {0.5…1.25} | ς=0.75（1 折 0.5） | −2.65U | [−16.22, +6.94] | −5.23 / +2.58 | 0.6434 | ❌ |
| 地板阶梯（σ 三分位 ⇒ {0.80/0.83/0.86}） | 3 档 + 单调性 | 3 折「全 0.83」（= 现行），1 折「σ 小⇒严」 | −2.11U | [−6.33, 0.00] | −2.11 / −0.00 | 0.9202 | ❌ |

**读法**：
- **只有 `walk ≥ χσ` 这一轴有信号**，且方向与决策 #29 一致（σ 归一化的闸）；χ=0.8 在
  **五个折里都被独立选中**（不是一格噪声）。但它 **Δ 的 95% 下界 < 0**、**分半反向**
  （+11.69 / −5.92）、净 Δ +5.76U **低于 +10U 门槛** ⇒ 四条判据①④②全不过。
- ⚠️ **`χ=0.8` 与现行 `43$` 的关系**（**窗前** σ 中位 **62.91$**，均值 71.32$）：
  `43$ = 0.683σ`；而 `0.8σ` 折美元的四分位是 **[32.6, 50.3, 71.2]$** ⇒ 它在**中位窗上更严

### 6.2 最重要的一条：**市价就是基准，GBM 没能跑赢它**

- tick 级 AUC：模型 0.8789 / **市价 0.8807**；Brier 0.069142 / **0.068224**；
  logloss 0.222880 / **0.221651** —— 三项**全面略输**。
  **B2（整窗 + 官方标签 + 双侧）复现同一条**：AUC 0.8950 / **0.8996**，
  Brier 0.132086 / **0.129313**，重要度 **86.47%** 回到价格本身。
- 🆕 **B2 把这条推到了它的自然结论**（§4B.5）：模型自报的「胜率」与那一秒的要价
  **逐桶相等**（98.61% vs 0.982 … 65.26% vs 0.634）⇒
  **「胜率」这个量已经被价格完整编码**，因此「给胜率最高的信号」= 「买最贵的那一刻」：
  能买到 99.92% 胜率，但每注只赚 1.1%，而链 97.83% 胜率每注赚 1.7%。
  **胜率与每注收益在这个市场里是反比的两件事**，没有「又高又便宜」的解。
- 特征重要度 75.65% 在 `fill` 本身 ⇒ 模型学到的主要是**市价的复述**：13 个非 `fill` 特征
  合计只占 **24.35%**，其中 5 个动量/成交量特征（`walk_chg_10s` / `vol_rate_30s` /
  `vol_ratio_prev` / `spot_ret_10s` / `dev_chg_10s`）合计 **4.80%**。
- 实盘一侧同样：core 模型 AUC 0.8296 < 市价 0.8572。
- 这与项目已有机制**完全一致**（memory：**PM 领先 TWAP、市场以 Chainlink TWAP 结算**；
  `docs/tail_entry_timing_2026-09-29.md` 的核心机制「**便宜价编码的是『还没定局』**」）：
  热门侧价格已经是市场对「结算线会不会站住」的充分统计量。**要跑赢它，需要的是它没含的
  信息（现货/订单流/执行面），而不是更强的函数类。**

### 6.3 Track B 失败的机制（为什么「模型有判别力」也会亏）

1. **规则形态自带逆向选择**：`p̂ − fill > δ` + 「首个满足即买」= 在每一格里买**最便宜的
   tick**。入场 fill 中位 **0.86**（链是 0.99），WR 81.66% ⇒ 2U/注下这是全部亏损来源。
2. **模型自称的边蒸发**：自称 `p̂ − fill = +2.6pp`，实现 `WR − fill = +0.1pp`。
   校准缺口**确实**随 `(p̂−fill)` 上行（§7a：D1 −2.4pp → D7 +0.9pp），但量级 0.3~0.9pp，
   而 @0.98 的每笔盈亏比是 1:50。
3. **在链上做过滤（gbm.md 的原设计）也一样**：δ=0 只 +2.11U（区间含零），δ≥0.01
   **显著为负** —— 因为它删掉的正是「市价便宜」那批，而链随后会以更高价重入。
4. **δ=0.02 的 +37U 是搜出来的**：折内选择后 OOF 变 **−15.79U**、分半反向、p=1.0000。
5. 🆕 **B2 换了标签与朝向也躲不开它**（§4B.4）：模型选边的 P&L 有 84% 来自 `fill < 0.30`
   那 902 笔廉价彩票（每笔赢 +22U，+156U 只有 **1σ**）；同一个决策 tick 上，买热门侧
   WR 79.61% 却 **−29.05U** —— **「模型挑边」没有产生稳定 EV，产生的是尾部赔付**。

### 6.4 实盘一致性给出的**执行面**结论（比模型结论更有用）

- 按现行规则重放的实盘 864 条信号里，**45.9% 的有效价来自 bid 兜底**（回测=0），
  且 **p̂ 十分位 D10 的成交率 1.37%、bid 兜底 100%**：**模型最看好的那片区域，
  正是热门侧被买光/撤空（决策 #21）的区域**。
- ⚠️ 控制住这一点后（只看 ask 在场的行）**成交率与 p̂ 无关**（低半 86.2% / 高半 88.2%，
  ρ=+0.11）⇒ 逆向选择不是「模型看好所以买不到」，而是**「模型看好的地方本来就没有卖单」**。
- 因此：**回测里的 Track B 数字本身已经是上界**（回测挂单即成交），实盘只会更差；
  而真正的瓶颈是**可成交性**而不是**赢率预测**。

### 6.5 风险与局限（写进判据、不得事后放宽）

1. **样本**：14 天 / 2074 单 / **45 输单**；最小可检出 Δ ≈ **±9.8U** —— 小于这个量级的
   真实增益本轮**测不出来**（要 ~56 天）。Track A 的 +5.76U 正落在这个盲区里。
2. **tick 高度相关**：150 tick 共用一个标签 ⇒ 已经按 1/窗加权 + 窗口级评估，
   但 AUC 的置换 p=0.0050 是 **200 次置换的分辨率下限**（不是精确值）。
3. **只有 6 个 δ 格**：搜索校正把「挑格子」算进了 p，但**阈值族本身**（规则形态）的选择
   没有校正 —— 换规则形态（如「最后 N 秒才买」「p̂ 递增才买」）**没测**，属于后续可能。
4. **实盘 8 天不是干净前向**（规则三版本、成交内生、价位段与回测差 20k）⇒ §5 只作一致性
   检查，**不构成对模型的前向判决**。
5. **`fill` 的漂移还没被解释完**：PSI 2.11 里混着采样口径差（实盘只落决策点行）与真实
   价位段上移，两者本文没拆分。
6. **特征缺口**：σ 的**跨窗分位**只做到窗口级（Track A 的 σ 轴），没进 tick 特征；
   PM 盘口/深度的任何量在回测里都是零方差 ⇒ **回测永远测不了盘口类特征**，
   这类特征只能等实盘样本够了单独立项。

### 6.6 后续可能的方向（本轮没做，不为结论背书）

- **改标签而不是改模型**：现在的标签是 `P(赢)`，而实盘的钱在 `P(成交 ∧ 赢)` ——
  把 09-26 起有 `exec_status` 的实盘样本单独建模（先解决样本量）。
- **把「ask 撤空」当一等公民**：§5.3 说明它同时决定成交率与模型的有效域；
  `hot_src`/空侧深度目前只是审计字段。
- **现货/订单流侧的信息**：模型对市价无能为力，而 `data/events` 正在持续采集逐秒
  原始盘口与 Binance 成交 —— 这是**市价没含**的那部分。
- ⚠️ **不要再提**：「GBM 概率过滤候选信号」这条（§4.4 已显著为负）、
  「walk/dev 阈值 σ 动态化」这条（§3 已否）、**「从 0s 起喂整窗 + 官方 outcome 标签」**这条
  （§4B 已否，`06_full_window_gbm.py`）、**「让模型给胜率最高的信号」**这条（§4B.5：
  胜率已被价格编码，追胜率 = 追价格 = 每注只剩 1.1%）。换阈值/换格点/换标签朝向不算新机制。
