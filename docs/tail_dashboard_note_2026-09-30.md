## 2. 本窗曲线图（anchor / twap / spot 三线同轴 + 两条派生阈值线）

### 数据流

```
cmd/tail 主循环（1s tick）── runtime.sampleCurve(lastTick) ──▶ curveBuf（本窗缓冲）
                                                                    │
Dashboard 前端（1s 轮询）◀── /api/curve ◀── TailState.handleCurve ◀──┘
```

- **采样在服务端主循环**，不在前端攒点：主循环本来就 1s 一拍；前端若按 `/api/state`
  的 5s 轮询攒点，300s 的窗口只剩 60 个点（漏掉 4/5）。临界价更是**只能**在这里算：
  它要的是逐秒现货序列（见下），前端手上攒不齐。（外推临界价不欠这条——它只依赖
  当前 tick 的 spot/anchor/rem，前端也算得出来；放在这里是为了**两条派生线同一处口径**，
  加上 `.bit` 与画笔之外前端不持有任何公式。）
- 三个值都取自与判定路径同源的读数（`flip.Tick` 的 `BinPrice`/`TwapPrice` +
  `engine.WindowAnchor()`），但**不参与任何判定**：缓冲丢了只影响页面上那条线。
- `Spot = 0`（无推送/超龄）与 `Anchor = 0`（取锚通道命中前）原样下发，前端**断线不画**
  ——不把「陈旧价」画成曲线上的点（与引擎判现货缺失同口径）。
- **换窗**由服务端决定：`curveBuf.add` 见 `eventStart` 变化即整条换装；新窗第一个采样
  到达**之前** `/api/curve` 返回的仍是上一窗（`event_start` 与 `points` 都没变）⇒ 前端
  保留旧曲线不擦。这条语义由 `cmd/tail/curve_test.go` 钉住。

### 临界价（`P_required`）：现货要守在哪儿才结算 Up

公式（用户口径，`cmd/tail/curve.go` 的 `RequiredPrice`，`rem ≤ 60` 起才有值）：

```
P = (60 · TWAP_open − HistoricalSum) / rem
```

`HistoricalSum` = 结算窗里**已经定局那 (60−rem) 秒**的价格之和。推导：闭市那一刻的
TWAP-60 回看 60 秒 = 「已经定局的 (60−rem) 秒（和 = HistoricalSum）」与「未来 rem 秒
（全按 P）」⇒ 要求 `[HistoricalSum + P·rem]/60 = anchor`，解出 P 即上式。
**含义**：现货从现在起一直守在 P 之上不动 ⇒ 闭市 TWAP 恰好压在 anchor 上 ⇒ 结算 Up。

⚠️ **不要写成展开式**：`anchor + (anchor − past)·(60−rem)/rem`（`past` = 已定局秒的均价）
与它**恒等**（代入 `past = HistoricalSum/(60−rem)` 即得），但多一次「先除成均价、再乘回
秒数」的来回。**部分和形式正好是手上直接攒着的那个量**：缓冲里逐秒采的现货加起来就是
HistoricalSum，一次除法出结果。

三条边界：`rem = 60` ⇒ 一秒都还没定局、和为空 ⇒ `P = 60·anchor/60 = anchor`（起点必然
落在锚上）；`rem → 0` ⇒ 分母发散（只剩几秒要扳回整段偏差，这是真的，不是数值毛病）；
`rem > 60 / ≤ 0 / anchor ≤ 0` ⇒ 无定义返 0。

⚠️ **缺样本的秒要补**：逐秒采样会缺（推送断、超龄），`HistoricalSum` 若只把手上有的样本
加起来，`(60·anchor − HistoricalSum)` 会**凭空少掉整秒的价格**。故先算可得样本的均值
（`sum/n` = 每一秒的估计值）再乘回 `(60−rem)` 秒；样本数不足期望的一半（`2n < span+1`）
则整个点返回 0——宁可不画，不拿半截数据画一条看起来很像结论的线。

⚠️ **它是派生量，不是第四条读数**——三处口径为此让路（第 2 条 2026-09-30 当天由
「完全不进量程」改成「限幅参与」，起因见该条）：

- **数据来源是近似**：`past` 由**逐秒 Binance 现货**估计，而结算走 Chainlink 口径，
  两者有已知的水平差（memory「spot − TWAP 水平差」）⇒ 这条线的绝对位置带一个小幅系统
  偏移。**严格口径做不到**：上游只推 TWAP-60 本身，而 `TWAP60(t)` 的相邻差分只给出
  `x(t) − x(t−60)`，逐秒价反解不出来。这条线**不参与判定、不进 P&L**，就是看图用的。
- **在 y 量程里限幅参与**（2026-09-30 修，`app.js` 的 `TIE_ROOM`）：量程以**三条实测线**
  为基准，临界价**也参与**，但它在量程里的**取值先夹到三线 span 的 ±`TIE_ROOM` 倍以内**
  再取 min/max（默认 `0.5` ⇒ 量程最多涨到三线 span 的 2 倍 ⇒ 三条实测线至少占约 1/3 图高）。
  超出这一限幅的部分仍旧**裁到绘图矩形内**（线扎到画框边缘就没了 = 量程都装不下它，
  确切数字去悬停读数行看）。
  - **`TIE_ROOM` 为什么取 `0.5`**：拿真实窗逐档扫过（`0 / 0.15 / 0.25 / 0.35 / 0.5 / 0.75 /
    1.0`）——`0.25~1.0` 在真实数据上给出的是**同一个量程**（步长取整 `niceStep` 把它们吸到
    了一起），而 `0.5→1.0` 换来的可见秒数是 **41s → 41s**（一动不动），代价却是三线占高
    36% → 26%。`0.5` 落在平台中段，最不易被某一次取整甩出去。
  - **实测收益**（真实窗 `22:50:00` 那窗，三线 83668.06–83884.00、锚 83668.44）：
    量程从 `83600–84000`（步长 100）变成 `83400–84000`（步长 200），临界价**可见秒数
    21s → 41s**（最后一个仍在量程内的点 `rem 40 → rem 20`），三线占高 54% → 36%。
    `rem < 20` 那段仍然裁掉——那是限幅在起作用，不是残留的 bug。
  - **起因**：原先「完全不进 y 量程」⇒ 临界价一涨出三线范围就只剩一截断头线挂在画框下沿、
    之后全被裁掉。实测该窗 `rem=19` 时它已跌到 **83204.63**，而三线下沿是 **83532.47**
    ——整条线实际只可见十几秒，剩下的四十多秒画面上什么都没有，**与「无数据」的断线长得
    一模一样**（两者都是不画），读图的人只能当成 bug。
  - **为什么不是干脆全额放进量程**：它在 `rem→0` 时发散（要几秒扳回整段偏差；`rem=5`
    放大 11 倍、`rem=1` 放大 59 倍）。全额取 min/max ⇒ 尾盘那几秒把量程拽到几千美元宽，
    三条价格线压成一条平线，**整窗**都读不了了。
  - **为什么用夹取，而不是「撑破上限就退回三线量程」**：夹取是**连续**的——量程随临界价
    平缓长大、到顶后停住；阈值式退回会在触顶那一秒让整张图**跳一下**。
  - 三条实测线仍有**全量**的取值自由（夹取只作用在临界价身上）；代价是量程现在会随着
    临界价**变宽并向那一侧平移**——取的是**全窗** min/max，临界价一路跌，量程下沿就一路
    跟下去（到限幅顶为止），不再是三线内部的小幅微调。
- **不占第 4 个分类色槽**：分类槽 4（黄 `#c98500`）在本表面上与橙色的色盲分离度只有
  ΔE 4.8（低于 6.0 下限），换洋红更差（与水绿 1.6）——第四个**可区分**的颜色在这张图上
  不存在。阈值本来也不该用「序列」的画法：改走中性墨色 `--c-tie #8b949e` + **虚线**，
  与实测线在**形状**上区分（图例色块同款画成虚线条）。三条实测线的蓝/橙/水绿维持
  原样、原校验结论不变。

### 外推临界价（`S_required`）：按当前速度走，进入最后 60s 时得站上哪儿

公式（用户口径，推导见 `docs/Price_required.md`；`cmd/tail/curve.go` 的 `ExtrapPrice`，
`rem ∈ [60, 150]` 才有值，其余恒 0）：

```
S = Spot · (1 − k) + TWAP_open · k        k = (rem − 60) / (rem − 30)
```

**含义**：假设现货从此刻起保持当前速度 `v` 线性运行，最后 60s 的均值就是它中心点
（距现在 `rem−30` 秒）处的价格 `S₀ + v·(rem−30)`；要求它等于 `anchor`，解出临界速度
`v_critical = (anchor − S₀)/(rem−30)`，而**进入最后 60s 那一刻**（距现在 `rem−60` 秒）
的价格就是上式。等价说法：**当前速度必须 ≥ `v_critical`**。

⚠️ **它和上面的临界价不是同一个量，两条线合起来拼满整窗**——而且正好对上三段链的
两个检查点：

| 线 | 定义域 | 假设 | 检查点 |
|---|---|---|---|
| 外推临界价 | `rem ∈ [60, 150]` | 运动**继续**（保持当前速度） | 第一个判定点 T=150 |
| 临界价 | `rem ∈ (0, 60]` | 运动**停住**（守住一个价） | 第二个判定点 T=60 |

两者的假设正好相反，所以 **`rem = 60` 处二者的值不相等**：临界价 = `anchor`
（守住在锚上就结算 Up），外推临界价 = `Spot`（只剩「现在」，速度来不及起作用）。
画面上是两条线在 t=240s 处一上一下错开——**不是断线也不是 bug，是两个问题的答案本来
就不同**。真实窗（`22:50:00` 起，锚 `83668.44`）实测：

| 窗口内秒 | rem | 现货 | 外推临界价 | 临界价 |
| ---: | ---: | ---: | ---: | ---: |
| 150 | 150 | 83820.28 | **83706.40**（= 0.25·现货 + 0.75·锚，离结算最远 ⇒ 权重最大） | — |
| 200 | 100 | 83820.74 | 83733.71 | — |
| 240 | 60 | 83820.74 | **83820.74**（= 现货，收线） | **83668.44**（= 锚，起线） |
| 270 | 30 | 83806.20 | — | 83539.09（继续向下发散） |

形状一句话：**从锚附近起步，一路收窄到现货线上**（`k` 从 0.75 单调降到 0）。

⚠️ **它不需要任何量程照顾**：系数 `k ∈ [0, 0.75]` ⇒ 它恒是 `Spot` 与 `anchor` 的
**凸组合**，而这两个值本身就在三线的 min/max 里 ⇒ 它永远落在三条实测线之间（真实窗
实测：外推范围 `[83706.40, 83820.74]`，三线联合量程 `[83668.06, 83884.00]`）。
同一条窗里临界价最低跌到 `83006.38`——比三线下沿还低 662 美元，那才是需要 `TIE_ROOM`
限幅的那个。前端仍把外推线放进限幅那一关，但那是**恒等变换**：只为「派生量统一处理」，
不是它需要。

### 画法与取舍

- **y 量程按数据自适应**：三条实测线都是 BTC 价格（十万量级），彼此常常只差几十美元——
  固定量程会把三线画成一条。代价是量程会随窗口移动，用「取整到 1/2/5×10ⁿ 的整数步长」
  把它压到不晃眼。
- **x 轴 = 窗口内秒 0→300**（`window_sec` 由服务端下发，前端不硬编码）。
- 缺读数处**断线**；网格是实线发丝线（虚线会读成阈值/预测）——**网格不用虚线这条规矩
  只管网格**，两条派生线是**真的**阈值，虚线正是它们该有的编码。派生线的定义域不重叠，
  所以「每条只剩半窗有值」是常态而不是缺数据。
- 画序：派生量**垫在最下面**（临界价 → 外推临界价），三条实测线压上来；悬停时派生量画
  **空心点**（与虚线同一套「这不是读数」的编码）。
- **悬停 / 触摸**出竖直准星 + 点 + 线下读数行
  （`t=200s · 锚 … · TWAP … · 现货 … · 临界价 … · 外推临界价 …`）。不弹浮窗：小屏上浮窗
  会盖住曲线本身，且读数行与曲线同宽、不挡图。不在定义域里的那条显示「—」。
  - **每项包一个 `.bit`（nowrap）**：5 项在手机（390px）上必然折成两行，折点只能在
    **项与项之间**——不加这层会出现「现货」在行尾、它后面那个数跑到下一行开头。
    分隔符 `·` 用 `.bit::before` 挂，跟着后一项走，不会孤零零留在行尾。
  - **窄屏（≤480px）常态就占住两行高度**（`min-height: 34px`）：触摸设备上按一下就
    把卡片下面的内容顶下去一行，比多占 17px 难看得多。
- **配色**（蓝 `#3987e5` / 水绿 `#199e70` / 橙 `#d95926`）不取自页面既有 accent 色，
  而是分类槽 1/2/3：页面现成的 `--accent #58a6ff / --pos #3fb950 / --down #d29922`
  这套在暗面 `#161b22` 上跑 dataviz 校验器**不合格**（绿↔黄的色盲分离度 ΔE 5.1，
  低于 6.0 下限；三色亮度也都出了暗色带）——三条紧贴的线正需要这个分离度。
  **换色或换表面色前必须重跑 `scripts/validate_palette.js`**（用法见 `style.css` 注释）。
- **两条派生线共用一支中性墨色，靠虚线节奏区分**（长划 `[5,4]` vs 点线 `[1.5,3.5]`；
  图例色块同款两种节奏）：第 5 条线**也没有**新的分类色可用——不是「懒得多挑一个色」，
  而是第四个可区分的色相在这张图上**不存在**（见上面「不占第 4 个分类色槽」那条），
  第 5 个更不用说。形状本来就是阈值该用的编码通道。
- ⚠️ **图例容器的 `white-space: nowrap` 必须只加在每个条目上**：加在容器上会让图例的
  最小宽度 = 它的整宽，flex 于是去挤标题——390px 下实测标题「本窗曲线 · 22:50:00 起 ·
  289 点」被压成一列三行。正确做法 = 容器 `flex-wrap: wrap`（条目之间换行）+ 条目
  `white-space: nowrap`（条目内部不折）；`.curve-head` 也要 `flex-wrap: wrap`，
  5 项图例在窄屏整体落到标题下一行。图例在 §3 之后改由 `SERIES` 生成（两处用同一份）。

## 3. 点行看曲线：信号表 / 决策表任意一行 → 弹窗画那一窗（2026-10-01，决策 #31）

**做什么**：点信号表或决策表的任意一行，弹出一个窗口画**该行所属窗口**的完整曲线
（五条线同主图）+ 一条标出「这一行发生在第几秒」的竖线。用途是事后复盘：这一笔是在
曲线的哪一点下的、当时现货与结算线是什么姿态。决策行的价值更高——250 行
`walk_low`（入场闸不过）在表里只是一行字，画出来才看得出「当时结算线基本没动」。

### 为什么必须是「回读采集」而不是「多留几窗在内存里」

`curveBuf`（`cmd/tail/curve.go`）**只保当前一窗**：见新窗整条换装（§2 的换窗语义）。
本族一窗最多下一单 ⇒ 信号表 50 行里**最多 1 行**能画，功能会退化成「只能看刚刚那一笔」。

解法不新落任何盘：`cmd/tail` 自己就在当采集器（决策 #27），每秒原始采样落
`data/events/events_<UTC日>.jsonl`，每窗一行，行内**逐秒**含曲线三条实测线的全部输入：

| 曲线要的 | events 行字段 |
|---|---|
| 锚 | 顶层 `twap_open_price`（`anchor_source:"push"` = 引擎用的那条精确边界推送） |
| TWAP | `ticks[i].twap.price` |
| 现货 | `ticks[i].bin.price` |
| 横轴 | `ticks[i].ts` / `ticks[i].rem` |

⇒ 历史窗**纯读**重建。决策 #30「曲线是纯旁路、不写文件」那条红线**不碰**：新增的是
**读**，写侧一个字没改。

### 两条路（服务端定，落在 `source` 字段）

| `source` | 什么时候 | 前端副标 |
|---|---|---|
| `live` | 请求的那一窗**正是内存里这一窗**（`Curve().EventStart == event_start`） | 实况采样 |
| `events` | 否则从 `events_*.jsonl` 重建 | 原始采集重建 |
| `none` | 原始采集未开启 / 那天没文件 / 该窗没被采到 / 被落盘红线丢弃 | 无数据 + `note` 说明原因 |

`none` 也照 HTTP 200：`note` 是**要显示给用户的原因**，不是错误。
实况优先的理由：**它才是当时屏幕上那条**（含引擎对超龄现货的钳零口径），也比磁盘重建准。

### 口径差异（弹窗里以 `note` 明示，不藏）

重建取的是**原始值**（events 落 `LatestData()` 原值），实况曲线取的是引擎看到的 tick
（现货超龄会被钳 0）。⇒ 重建线**更完整、断点更少**，锚从**第一秒就有**
（events 是窗末组装；实况要等取锚通道 +2s）。看图形足够，**不等于**当时页面上那条。

⚠️ **两个坑**（都写了注释，别踩回去）：

1. **归日只认窗口起点**。events 文件按 `DayForStart(start_time)` 归日，而行的 `date` 是
   **行 ts** 的 UTC 日——跨午夜的窗两者差一天。所以 `/api/signals`、`/api/snaps` 里
   下发的是 `event_start`，前端点行时**只能**用它去定位文件。旧口径的行（`kind=frame`/
   `scan`）没记 `event_start` ⇒ 弹窗说明「无法定位窗口」，不猜。
2. **`TieAt` 的契约是「`pts` 不含本点」**（本点由 `cur` 传参）。实时路径那一刻缓冲里
   还没追加本点；重建路径必须传 `pts[:i]`——传 `pts[:i+1]` 会把本点算两次
   （`TestTieAtExcludesCurrentPoint` 钉住）。

### 四类「没有曲线可看」

① 该进程 `runtime.events_dir` 是空串（采集关着）；② 那天的文件不存在（本机只有
09-27 / 09-30 起有）；③ 该窗没被采到（跳窗路径从不产出行）；④ 被落盘红线丢弃
（锚 ≤ 0 / `binance_open` ≤ 0 / tick 数不足）。**四类在弹窗里长得一样**——一行 `note`
说清是「没有采集」而不是「采集了但画不出来」，前者用户无能为力，后者才是 bug。

### 实现与成本

- 纯函数与共享公式：`internal/tail/curve.go`（`RequiredPrice` / `ExtrapPrice` / `TieAt`
  + `WindowSec` / `TwapLookbackSeconds`；`cmd/tail` 的常量改成别名，**一份公式两处用**）。
- 回读：`internal/collect/query.go` 的 `LoadEventByStart(dir, startTime)`——逐行子串预筛
  `"start_time":N,`（**必须带分隔符**，否则 1000 会命中 10001），命中才 unmarshal；
  scanner 缓冲显式提到 16MB（**一行实测 ~210KB，默认 64KB 直接 token too long**）。
- 路由：`internal/dashboard/tail_curve.go`（`/api/curve` 加 `event_start` 参数；
  无参数 = 主图那条 1s 轮询，行为一字未变）。`TailState` 只多一个**只读**的 `eventsDir`。
- **成本实测**：5.8MB 的当日文件扫到目标行 **26ms**（整窗 300 点返回）。满一天 288 窗
  ≈ 62MB ⇒ 百毫秒级。**不做缓存**——用户点一下的代价，不值一个索引。
- 依赖方向：`internal/dashboard → internal/collect`（后者只用标准库，无环）；
  `tail.Snapshotter` 接口**没动**（重建在 handler 层）。

### 前端

- **单击打开**（不用 `dblclick`）：双击的第一次 `click` 也会开，所以「双击」照样能用；
  而 iOS Safari 的双击是**缩放**，`dblclick` 不可靠。行上挂 `data-es` / `data-ts` +
  `row-click` 类（`cursor: pointer` + 与逐日明细同款的悬停底色——没有它看不出能点）。
- **委托绑定**在 `#signalsTable` / `#snapsTable` 上各一次：表体每 15s 整块重渲染，
  逐行绑定会全丢。
- **弹窗图不轮询**：它是冻结的历史窗，1s 的 `/api/curve` 只喂主图。**先解锁遮罩再画**
  ——`hidden` 时 `clientWidth === 0`，`drawChart` 会直接 return。
- **一条绘制代码两张图**：`makeChart(cvId, roId)` 出实例（`data` / `hover` / `geom` /
  `mark` / `empty`），`drawChart(ch)` 不再认 `#curveCanvas`。原来是模块级单例
  （`CURVE`/`hoverIdx`/`geom`），两张图并存时悬停下标会**串台**。
- **标记线（`ch.mark`）画在网格之上、五条线之下**：它是**注释**不是数据序列，压在上面
  会把「那一刻价在哪」盖住。与悬停准星**同色**，靠**顶部小标签** `t=239s` 区分
  （准星没有标签）；**不占第 4 个分类色槽**（那支中性墨色本来就是给派生线用的）。
- **`Esc` 与遮罩空白点击两个弹窗都关**（原先 `Esc` 无条件只关逐日明细）。
