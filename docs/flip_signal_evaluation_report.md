## 七、被过滤器拦截的翻转 — 根因分析

### 7.1 各过滤器触发的比例

逐个分析被拦截的真实翻转（FN=392），统计各过滤器的触发频率：

| 过滤器 | 条件 | 占被过滤翻转的比例 | 评估 |
|--------|------|-------------------|------|
| **`other_delta < 0.03`** | 对手方 5s 内无明显反拉 | **~70%** | 🔴 过度严格，最大杀手 |
| **`noise_ratio > 3.0`** | BTC 路径噪声大 | **~35%** | 🟡 可放宽到 5.0 |
| **`path_eff < 0.4`** | BTC 趋势不明确 | **~25%** | 🟢 基本合理 |
| **`min_pre_snaps < 5`** | 穿越发生在周期太早期 | **~8%** | 🟢 合理 |
| **Score < 5** | 综合评分不够 | **~6%** | 🟡 可降低门槛 |

*注：一个信号常被多个过滤器同时拦截，故比例之和 >100%。*

### 7.2 `other_delta` 的深层问题

`other_delta` 是本策略最大的"杀手" — 约 70% 的真实翻转因为它 < 0.03（或为负）而被拦截。

**原因分析：**

1. **T+5s 窗口太短**：对手方价格在 5 秒内的反应与最终结果相关性很弱。很多翻转要等到 30s~60s 后对手方才开始明显移动。
2. **other_delta 为负不代表不会翻转**：很多被拦截的信号，对手方在 T+5s 时微跌（`other_delta = -0.01 ~ -0.05`），但最终涨到了 1.0。
3. **当前 other_delta 阈值是离散二元判断**：`>0.03 → +4分`, `>0.01 → +2分`, 其他 → 0分（然后被硬拦截）。这导致大量 other_delta=0.02 的翻转机会被丢弃。

### 7.3 典型被误杀案例

```
✅ 翻转成功, 被 other_delta < 0.03 + score < 5 拦截:
   0x4526a81c | cross=no @ rem=166s → outcome=YES (YES 赢了)
   path_eff=0.825  noise_ratio=2.95  other_delta=0.040  entry=0.280
   → other_delta 0.04 > 0.03 → F1 触发 +4 分
   → 但 entry=0.28 > 0.25 → 没有 F5 加分
   → 没有振荡 → 没有 F3
   → 总分 = 4, 刚好 < 5 → 被拦截！（差 1 分）

✅ 翻转成功, 被 noise_ratio > 3.0 硬拦截:
   0x851f2267 | cross=no @ rem=167s → outcome=YES
   path_eff=0.509  noise_ratio=4.87  flips=5  other_delta=-0.030  entry=0.270
   → noise_ratio 4.87 > 3.0 → HARD VETO
   → 但最终翻转成功。noise_ratio 高恰恰说明 BTC 在剧烈震荡，
      这正是 flip 策略希望看到的"过度反应"前兆。

✅ 翻转成功, 被 path_eff < 0.4 拦截（差一点点）:
   0x03e68dd | cross=yes @ rem=162s → outcome=NO (NO 赢了)
   path_eff=0.380  noise_ratio=2.64  other_delta=0.040
   → path_eff 0.38 < 0.4 → HARD VETO
   → 仅差 0.02 就被彻底排除
```

## 八、入场时间 vs PM 价格轨迹

### 8.1 为什么 Early 信号输了？

对比早期信号 (>240s) 和晚期信号 (<120s) 的 PM 价格轨迹：

```
[EARLY] LOST — 08:20:33 | cross=yes
  触发方(YES): 0.78 → 0.99  (继续涨, 没有 retreat)
  对手方(NO):  0.21 → 0.00  (对手方归零)
  BTC 移动:    +0.038%      (几乎不动)
  → PM YES 涨到 0.99 后不再回头，没有给对手方任何机会

[LATE]  WON  — 21:13:44 | cross=no
  触发方(NO):  0.89 → 0.00  (彻底翻转!)
  对手方(YES): 0.10 → 0.99  (对手方涨到 1.0)
  BTC 移动:    +0.046%
  → 距离收盘很近，PM 的极端定价没有时间维持
```

**失败模式**：Early signal 触发后，PM 的 0.7+ 价格往往 **继续冲高到 0.99+ 而不是翻转**。因为还有 4 分钟，市场还有时间继续向原有方向走。

**成功模式**：Late signal 触发时距离收盘很近，PM 已经没有时间纠正错误定价，最后的 BTC 微动就能让价格彻底翻转。

### 8.2 全部 26 笔信号的触发方 retreat 情况

| | Won (n=11) | Lost (n=15) |
|------|------------|-------------|
| 触发方平均 retreat | **+0.75** (完全翻转) | **-0.23** (继续冲高) |
| 对手方平均 move | +0.75 | -0.23 |
| BTC post-entry 移动 | -0.055% (向反方向) | +0.040% (向同方向) |

> Won 和 Lost 在触发方的行为上有**质的区别**：Won 的触发方中位数 retreat 是 +0.74（回到 0.0），Lost 是 -0.22（继续冲高到 0.99+）。这是一个根本性的二分类问题。

## 九、参数优化建议

### 9.1 立即可以调整的低风险优化

| 参数 | 当前值 | 建议值 | 预期效果 | 风险 |
|------|--------|--------|----------|------|
| `ScoreEntry` | 5 | **6** | Score=5 胜率仅 33%，提高到 6 后 precision 提升 | 信号频率降低 |
| 新增：`remaining_sec` 硬过滤 | 无 | **>240s veto** | >240s 胜率仅 12.5%，过滤后总 PnL +5.91 | 漏掉 ~30% 信号，但大多是亏损的 |
| `NoiseRatioOscillating` | 5.0 | **2.5** | 让 F3（振荡加分）生效，激活一个全新特征维度 | 低 |
| `PathEffOscillating` | 0.5 | **0.6** | 配合上条，适度放宽振荡检测 | 低 |

### 9.2 需要更多数据验证的中风险优化

| 参数 | 当前值 | 建议值 | 预期效果 | 风险 |
|------|--------|--------|----------|------|
| `OtherDeltaStrong` | 0.03 | **0.02** | ~70% 的翻转被 0.03 拦截，降到 0.02 可大幅提升 recall | FP 可能增加 |
| `OtherDeltaWeak` | 0.01 | **0.005** | 配合上游，让更多边缘信号至少拿到 2 分 | FP 可能增加 |
| `noise_ratio` 硬 veto | 3.0 | **5.0** | 当前 35% 翻转因 noise>3 被拦，但 noise=3-5 胜率反而高 | 低风险，noise_ratio 已非主过滤器 |
| `ConfirmDelayTicks` | 1 (5s) | **3 (15s)** | 5s 太短，对手方需要更长时间反应 | 延迟入场，rem 更少 |
| `FlipsOscillating` | 2 | **3** | 配合振荡检测放宽 | 低 |

### 9.3 需要重构的方向性改进

| 改进项 | 说明 | 优先级 |
|--------|------|--------|
| **other_delta 改为趋势检测** | 不只是看 T+5s 单点变化，而是看 T+5s~T+15s 的斜率。对手方持续推高 → 即使绝对值小也应给分 | P3 |
| **动态时间权重** | remaining_sec 越少，信号 confidence 越高。不要让 >240s 直接 veto，而是降低下注量 (0.5 share) | P3 |
| **BTC 微观结构确认** | 在确认窗口中检查 signed_flow、depth_imbalance 是否支持翻转方向 | P3 |
| **分时段参数** | 亚洲早盘和欧美时段使用不同的 Score 门槛 | P2 |

### 9.4 参数调整的优先级路线图

```

  ├── ✅ ScoreEntry: 5 → 6
  ├── ✅ 新增 remaining_sec > 240 veto
  ├── ✅ NoiseRatioOscillating: 5.0 → 2.5
  └── ✅ PathEffOscillating: 0.5 → 0.6

Week 2 (积累100+笔后):
  ├── noise_ratio veto: 3.0 → 5.0
  ├── OtherDeltaStrong: 0.03 → 0.02

  ├── other_delta 趋势检测

```

## 十、结论

### 是否可以实盘？

#### 🔴 暂不建议实盘，核心原因有三：

1. **Recall 太低 (3.7%)**：当前参数下，策略只抓到 3.7% 的翻转机会。过于保守意味着实际交易频率极低（416 个市场仅 26 个信号）。

2. **统计不显著**：26 笔交易，t-stat 仅 0.39。最后 7 连赢贡献了 81% 的利润，不能排除运气成分。至少需要 100+ 笔交易。

3. **时间偏差**：亚洲早盘 (00-08 UTC) 全败，欧美时段 (17-22 UTC) 全赢。全天运行的话特定时段会持续亏损。

#### 🟢 但策略逻辑是正确的：

- **76.2% 的 0.7 穿越最终翻转** — 核心假设被数据验证
- **盈亏比 3.4:1** — 即使胜率只有 30%+，靠盈亏比也能盈利
- **过滤器 specificity 91.3%** — 假信号拦截率很高
- 问题不在逻辑，在**参数过于保守**

### 路线图

```
当前状态:  纸交中, 26笔信号, PnL +5.05, 胜率 42.3%
           ↓ P0: 应用低风险参数优化
1周后:     目标 100+笔信号, 重新评估 precision/recall
           ↓ P1: 应用中风险参数优化  
2周后:     目标 200+笔, 统计显著 (t > 2.0)
           ↓ 最终评估: 是否可以实盘?
```

> **一句话总结**: 策略核心逻辑正确（PM 0.7+ 穿越后 76% 翻转），盈亏比优秀 (3.4:1)，但当前参数过度保守导致只捕捉到 3.7% 的机会。建议先放宽最严格的过滤器（other_delta, noise_ratio），再积累 100+ 笔纸交数据后重新评估是否可以实盘。
