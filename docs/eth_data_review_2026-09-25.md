## 4. 尾盘整侧撤空：服务器数据复现（决策 #21 的 ETH 侧取证）

### 4.1 证据链

先排除假象：§3 的 25 个全零 tick 不是撤空。真正的撤空族：

| 量 | 实测 |
|---|---|
| 段数 | **30 段**（散在 23 个窗里） |
| 覆盖 tick | **1482 / 6900 = 21.5%** |
| 起始 rem | 0 ~ 137 |
| 段长 | 中位 **56 秒**，最长 137 秒 |
| 是否回填 | **22/30 一直空到闭市**，8 段中途回填 |

四条独立证据：

1. **镜像 100% 成立**——所有缺腿 tick 都是「**赢家卖腿 + 输家买腿**」成对为 0
   （`outcome=0` 时 `yes_ask`+`no_bid`，`outcome=1` 时 `no_ask`+`yes_bid`），
   1534 个非全零缺腿 tick **零例外**。这正是决策 #21 在 BTC 上描述的形态。
2. **互补恒等式精确成立**——四档齐全时 `|yes_bid + no_ask − 1|` 的 p99 偏差
   **0.0000**（最大 0.01）⇒ 两本簿是同一本簿的两面，两侧同时消失不是巧合。
3. **与市场定局精确耦合**——**30 段里 29 段的起点，热门侧价已经 ≥0.96**
   （中位 0.98）；唯一例外是末窗 rem=6 的 6 秒残段（0.90）。
   ⚠️ **这一条是关键**：网络抖动/丢消息会在任意时刻、任意价位发生，
   不会精准地贴着「市场刚定局」发生。
4. **数据来自服务器**（非本机）——排除了决策 #23 §5.5 留下的
   「可能是我本机网络问题」这一支。

⇒ **结论**：现象为真，且是市场性的。决策 #21 的双通道取证在 ETH 上得到独立复现。

⚠️ **仍未证的是「比率」而非「现象」**：持有空快照的时间可能长于市场实际
（我们收不到回填消息时，会继续显示空）。BTC 那次有用公共 REST 复核过一窗；
本次**没有**再做 REST 复核（用户判断本机网络不好、不必本机测试）。
故 21.5% 这个数是**指示性的上界**，不是估计量——先用它做决策，不用它做参数。

### 4.2 对两条策略的量化影响

| 策略 | 关键时段 | 实测 | 结论 |
|---|---|---|---|
| **狗@0.2** | `rem > 180` | 四档齐全率 **2689/2714 = 99.08%**（只丢 0.92%） | **基本不受影响**——缺腿全落在策略不交易的尾盘 |
| **扫尾盘 ⑤** | `rem ≤ 60` | 热门侧有效价 ≥0.80 的 tick 里，热门侧**没有卖单**的占 **1148/1389 = 82.6%** | **信号条件与「买不到」几乎重合** |
| 同上 | `rem ≤ 150` | 1534/3045 = **50.4%** | |
| 同上 | `rem ≤ 30` | 661/728 = **90.8%** | |
| 止损腿（决策 #24，未落引擎） | 出场瞬间 | 亏损侧 bid = 0 占 **1148/1426 = 80.5%**（rem≤60）/ 89.8%（rem≤30） | 那 +10.44U 是**硬上界** |

**扫尾盘还有一条更硬的**：决策 #22 给扫尾盘加了 **bid 兜底**（`HotBook`：有效价 =
`ask > 0 ? ask : bid`），而 BTC 的 14 天回测里 542800 个 tick 中「四档部分缺」**0 次**
——但决策 #23 已查明那 0 是**旧守卫丢弃空侧消息的构造性产物**，不是市场属性。
⇒ **那条兜底路径在现有回测数据里根本无法被触发**（parity 测试是平凡通过的），
而在 ETH 上它会成为**主要**路径（82.6%）。纸面按「有效价即成交」记账 ⇒
**ETH 上的纸面数字等于假成交，不可外推**。

**一个正面数**：热门侧**确实有卖单**时（`rem ≤ 60`，n=278），前 5 档深度中位
**230 股**、低于交易所下限（`minimum_order_size = 5` 股）的只占 **0.4%**。
⇒ 瓶颈是「**有没有人卖**」，不是「量够不够」。

## 5. 待办：ETH 扫尾盘阈值重标定（**等 ETH 采集 ≥14 天后做**）

### 5.1 为什么必须重标定

扫尾盘的 7 个配置键里，**5 个是无量纲/时间的，可跨标迁移**；**2 个是绝对美元，
不可迁移**：

| 键 | 值 | 可迁移？ |
|---|---|---|
| `t150_rem` / `t60_rem` | 150 / 60（秒） | ✅ |
| `price_min` | 0.80（概率） | ✅ |
| `max_book_lat_ms` | 300（毫秒） | ✅ |
| `stake` | 2（U，下注额） | ✅（是注量不是门槛） |
| **`dev_min_usd`** | **63（美元）** | ❌ **BTC 价格标定量** |
| **`sigma_min_usd`** | **40（美元）** | ❌ **同上** |

用引擎同一定义（前 ≤18 个已完窗 `|close − open| / open × 1e4` 的均值）实测：

| 标的 | 价格中位 | σ 中位 | σ 折美元 |
|---|---|---|---|
| BTC（14 天，n=3750） | 77,235 | 8.10 基点 | **62.56 美元** |
| ETH（首批，n=20） | 2,692 | 19.95 基点 | **5.36 美元** |

⇒ 在 ETH 上：分支 A（`dev ≥ 63 美元`）要求 **11.7 倍中位 σ** 的位移
（ETH 全样本窗口位移 p90 才 **10.00 美元**）；分支 B（`sd ≥ 40 美元`）要求
**σ ≥ 148.6 基点**（ETH 实测 σ 的 p90 只有 **22.8 基点**）。
**两条腿都不可达 ⇒ 扫尾盘在 ETH 上等于开不出来**（不是参数偏，是量纲错了）。

两个折算锚点（⚠️ 只作交叉验证用，**不作结论**）：

- 按**基点**折算（价格比 2692/77235）：63 → **2.18 美元**，40 → **1.39 美元**
- 按 **σ** 折算（σ 比）：63 → **5.40 美元**，40 → **3.43 美元**
- 两者差 **2.5 倍** ⇒ 说明折算本身带歧义，**必须由 ETH 自身数据选**

### 5.2 前置工作（估计很小）

`python/v4/23_tail_integrated.py`（现行 oracle）里三处写死，参数化即可：

- 第 53 行 `DEV_USD = 63.0`、第 54 行 `SD_MIN_USD = 40.0` → 加两个 CLI 参数
- 第 196 行 `load_events("data/btc")` → 加数据目录参数
  （`13_tail_sweep.py` 已有 `--data` / `--stake`，可照抄）

### 5.3 预设判据（**先写死，再跑**）

**步骤 0 —— 可成交性先行（ETH 独有，必须先做）**

在标定任何阈值之前，先算「决策点可成交率」：对每个候选判定点
（`rem ≤ 60` 的首个可判定 tick），统计热门侧 `ask > 0` 的占比。

- ✅ **这件事 BTC 的 14 天数据做不到**（旧守卫让缺腿形态在数据里根本不存在，
  决策 #23），而新采的数据天然带这一列（决策 #21 的守卫修复）——
  **这是 ETH 数据唯一优于 BTC 历史数据的地方**。
- 判据：**可成交率 < 50% ⇒ 判「ETH 不可执行」，不进入阈值标定**
  （此时该做的是换标的或改策略形态，不是调参）。
- 首批 23 窗实测 82.6% 不可成交（§4.2），但 **2 小时样本太小**，
  该数只是指示性的上界，必须用 ≥14 天复算后作数。

**步骤 1 —— 网格扫描**

在 ETH 上扫 `(dev, sd)` 二维网格 + **日期级重采样 2000 次**
（方法同 `13_tail_sweep.py` 的 `boot_days` / 决策 #22 的 bootstrap 口径）。

**步骤 2 —— 判据**

- **必须报告 argmax 与平台宽度**，不接受单点 argmax。
  BTC 的教训：`40` 是噪声尖峰——真 argmax=35，2000 次重采样里 40 **一次没中**
  （故 BTC 侧「参数全部不可调」，决策 #17/#22）。
- 若 ETH 的 argmax **平台与某个折算锚点重叠** ⇒ 采信该折算值
  （跨标的一致性是对机制的正面支持）；
  **不重叠** ⇒ 以 ETH 平台为准，但必须同时给 bootstrap 区间与重采样分布。
- **交割口径必须用「热门侧有卖单」的子样本**（即 `hot_src == ask`）：
  ETH 数据做得到，BTC 回测做不到（原因同步骤 0）。这是 ETH 版回测与
  BTC 版**有意不同**的一条，须写进 ETH 侧的 mapping 文档。

### 5.4 决策表

| 步骤 0 可成交率 | 步骤 1/2 结果 | 判词 | 动作 |
|---|---|---|---|
| < 50% | 不进入 | **不可执行** | 不标定，另立项（换标的 or 改形态） |
| ≥ 50% | 有平台 ∧ n ≥ 800 | **标定成立** | 写 ETH 专用配置，纸面跑 |
| ≥ 50% | 无平台（argmax 随重采样跳动） | **不可辨识** | 只登记，不落引擎（同 BTC 的 `40`） |
| ≥ 50% | n < 800 | **样本不足** | 继续攒（§5.2 的 n ≥ 800 闸门来自 `tail_sweep` §5.2） |

**触发条件**：`data/eth` 连续 **≥14 个完整日**（≈4032 窗），且 tick 覆盖率
≥99%（每窗 300 tick 的窗占比）。**在此之前不做任何阈值分析**（本文件即该约定的凭据）。

  精确推送 20s 内没到时保留该近似值并标 `anchor_source=stream`、触发官方修正
