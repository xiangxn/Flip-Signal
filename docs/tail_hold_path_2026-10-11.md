## 0. 缘起：用户的命题（原文）

> 「根据这么多数据的验证，我觉得 dev、basis、walk、sd 做为扫尾盘策略的过滤条件其实是
> 没有科学依据的，只是从 data/btc 回测数据里拟合出来的一个基本无意义的数据。真正决定
> 扫尾盘是否成功的是持仓后，spot 是否有向不利的一方移动，总体来说跟 dev 没有直接关系，
> 只是当 dev 大 walk 也大时能接受的 spot 向不利方向移动的量更大一些。你看看能不能从
> 这个思路来监控数据。或者从 data/events 中的数据里找出新的办法来实现扫尾盘？」

**先定义四个量（全文同义）**，`sgn` = 押注方向（押 Up 为 +1、押 Down 为 −1）：

| 量 | 定义 | 现货语言 | 单位 |
|----|------|----------|------|
| `dev` | `sgn·(spot − anchor)` | 现货相对 **anchor** 的位移 | 美元 |
| `walk` | `sgn·(twap − anchor)` | **近一分钟均价**相对 anchor 的位移 = **趋势分量** | 美元 |
| `basis` | `sgn·(spot − twap)` | 现货相对**它自己近一分钟均值**的偏离 = **尖峰分量** | 美元 |
| `sd` | 窗振幅 σ 折美元（`hist_bps·anchor/1e4`） | 上面这些量的自然刻度 | 美元 |

其中 `anchor` = 窗口开局那一刻的 Chainlink TWAP-60 推送（决策 #15），`twap` = 窗口内
逐秒的 TWAP-60 推送。恒等式 `dev ≡ walk + basis`。

## 1. 结论摘要

1. **用户的「容忍度」模型是对的，而且是恒等式不是近似**：一笔注的结算余量
   `= dev0 + Δ`，赢 ⟺ `Δ > −dev0`（`Δ` = 持仓后现货的位移）。**`dev0` 本身就是
   「能承受的逆向移动量」**，不是它的代理量。`rem ≥ 60` 段还有 `dev(t) = dev0 + 现货位移`，
   即入场后实时 `dev` 就是「入场缓冲 + 已经走了多远」。实测 171133 个点，偏差 0.00e+00。

2. **用户说「过滤条件预测不了未来」也对**：结算线坐标下
   `corr(walk0/sd, Δwalk/sd) = −0.007`（≈0），`corr(basis0/sd, Δwalk/sd) = +0.121`
   （轻微延续，不是回补）。**任何从 dev/basis/walk/sd 造出来的过滤条件都无法预测持仓后的位移**
   ——它们只能决定 strike（也就是胜率），不能决定未来。

3. **市场价才是胜率的估计量，而且它比这些过滤条件更懂未来**：
   `corr(市场价, 结果) = +0.892`，而 `corr(状态量, 结果) = +0.609`；
   关键是 `corr(市场价, 随后 60 秒位移) = +0.222` vs `corr(walk60, 随后 60 秒位移) = +0.116`
   ⇒ **市场手里有状态量没有的未来信息**。任何由状态量构成的过滤条件，在这个意义上被价格支配。

4. **价格校准图（rem=150 / rem=60 两个判定点 × 两个样本，共 4 张）基本是平的**：绝大多数
   价档的「实际赢率 − 均价」落在 ±2 个标准误内。⇒ **在这些市场上，「价格 ≈ 胜率」是成立的**，
   所以一笔注的边际就是 `赢率 − 成交价`，能改善它的只有「用更便宜的价格买同一件事」。

5. **但直接检验「把价格按住，dev 还有没有用」→ 两个样本反号**：窄价档内二分，
   `data/events` 高档胜率高 **+2.0pp / Δ +44.24U**（日级配对 95% **[+15.56,+74.73]**，
   区间不含零，对桶宽 0.0025/0.005/0.01 与最小桶样本 5/8/12 全面稳健，15 天里 10 天为正，
   最大单日 +10.97U），而 `data/btc` 是 **−0.6pp / −14.05U**（**[−41.90,+11.30]**）。
   **反号 ⇒ 不是定律，是样本特性**。且 `walk0` 与 `basis0` **各自单独都分不开**
   （区间含零），只有两者之和 `dev0` 分得开——这个形状更像噪声而非结构效应。
   ⇒ **不建议据此再加一层 dev 过滤**。

6. **要监控的那个量是 `walk(t)`（计分板），不是 `dev(t)`（现货口径）**：入场后
   `walk(t) < 0`（当下结算就在输）**输单 87.7% 都出现过**（占持仓时长中位 15.9%），
   而赢单只有 6.8%；换成现货口径 `dev(t) < 0`，输单只有 **49.2%** 出现过。
   原因见 §7：现货口径带「Binance 现货 vs Chainlink 指数」的**水平差**，实测中位
   **+31.5 美元**（p25 +17.9 / p75 +53.1），它恰好把「差几美元」的贴线窗判反。

7. **「看着它跌就卖掉」这一族再次被否**（这是第三次独立证伪，见 §8）：
   按 `dev(t) < 0` 出场 Δ **+2.77U [−20.41,+1.30]**（救 25 输 / **杀 43 赢**）；
   按 `walk(t) < 0` 出场 Δ **−8.13U [−32.85,−6.85]**（救 24 输 / **杀 129 赢**）。
   原因与决策 #34/#39 一致：**你看见它跌的时候，市场已经报在那儿了**。

8. **前提复核（最要紧的一条）**：现行链在两个样本上的**每笔边际差 5 倍**——
   `data/btc` 毛 **+1.695%/笔**、`data/events` 毛 **+0.314%/笔**。
   按决策 #35 的官方手续费公式（Crypto 档 0.07）扣费：`data/btc` 净 **+1.434%/笔**
   （+59.47U / 2074 笔），而 **`data/events` 净 +0.058%/笔（+2.25U / 1959 笔）**——
   **最近 15 天的手续费（0.256%/笔）吃掉了全部毛边际（0.314%/笔）**，15 天里 8 天为负。
   ⇒ 「要不要找新办法」这个问题的前提本身已经变了。

## 2. 结构事实：结算到底取哪一段（三个独立实证）

这一节把「dev/walk/basis 是什么意思」钉死，后面所有推理都建立在它上面。

| # | 检验 | 结果 | 结论 |
|---|------|------|------|
| a | `|官方 twap_close − 窗口最后一个 twap 推送|` | 中位 **0.893 美元**，p90 3.63（n=3803） | 官方结算值就是闭市那一刻的 TWAP-60 推送 |
| b | `sign(twap_close − anchor)` 是否等于官方 outcome | **3803/3803 逐位一致** | **结算 = 结算线的最终位移**：赢 ⟺ `twap_close > anchor` |
| c | `corr(Δtwap, Δbin 瞬时)` vs `corr(Δtwap, (bin(t)−bin(t−60))/60)` | **+0.011** vs **+0.768**（斜率 0.918） | **`twap` 推送 = 过去 60 秒的均价**，它以现货 1/60 的速度移动 |

由 (c)：`walk` 是**一分钟均线相对 anchor 的位置** = 趋势分量；`basis` 是**现货相对自己
一分钟均线的偏离** = 尖峰分量（教科书里的 MA-deviation 振荡器）。

由 (b)：**结算只看最后 60 秒的均价** ⇒ 在 `T=150` / `T=60` 两个判定点上，当最后的
60 秒**一秒都还没开始**时，「现货此后一动不动」的结算余量**恰好等于 `dev`**。
这就是用户那句「dev 大 = 能承受的逆向移动量大」——它是**恒等式**，不是拟合出来的经验值。

## 3. 赌注的精确形式

```
现货坐标:    结算余量 = dev0 + Δ      , Δ     = sgn·(close − spot0)   ← 含水平差
结算线坐标:  结算余量 = walk0 + Δwalk , Δwalk = sgn·(close − twap0)   ← 干净
赢 ⟺ 余量 > 0
```

信号 n=1959（data/events，赢 1894 / 输 65）的中位数：

| 量 | 中位 | p25 | p75 |
|----|------|-----|-----|
| `dev0`（入场缓冲） | 90.1 美元 | 71.3 | 118.4 |
| `walk0` | 54.4 美元 | 25.9 | 86.8 |
| `basis0` | 45.4 美元 | 17.2 | 72.3 |
| `Δ`（持仓后现货位移） | **−33.6 美元** | −63.9 | +1.2 |
| `Δwalk`（持仓后结算线位移） | **+10.9 美元** | −3.9 | +32.3 |

两个刻度（这是全篇的骨架）：

- **strike 的尺度**：`dev0/sd` 中位 **1.69σ**（p10 0.86σ / p90 4.27σ）
- **未来的尺度**：`Δwalk/sd` 中位 **+0.19σ**、标准差 **0.76σ**（p10 −0.49σ / p90 +1.06σ）

⇒ 一笔注 = 「strike 有多少 σ」对赌「未来抽到多少 σ」。恒等式自检（`dev ≡ walk+basis`、
`余量 ≡ dev0+Δ`）**违例 0 条**。

## 4. 持仓后的位移可预测吗（用户命题的核心）

在**结算线坐标**下（去掉「Binance 现货 vs Chainlink 指数」的水平差），
`corr(·, Δwalk/sd)`，n=1959：

| 入场时的状态量 | 与未来位移的相关 |
|----------------|------------------|
| `walk0/sd` | **−0.007** |
| `dev0/sd` | +0.103 |
| `basis0/sd` | +0.121 |
| `fill`（成交价） | **+0.207** |
| `rem0`（入场剩余秒数） | −0.011 |
| `sd`（美元） | −0.049 |

**读法**：

- 状态量对未来**几乎无信息**（`walk0/sd` 的 −0.007 就是 0）。用户说「过滤条件预测不了
  未来」——**成立**。
- `basis0` 的 +0.121 是**轻微延续**（缺口不但不回补，还略微同向），所以「尖峰会消失所以
  别买」这个直觉在数据上不成立。
- **`fill` 的 +0.207 是唯一像样的数**：成交价越高，未来位移越有利 ⇒ **市场手里有过滤条件
  没有的信息**（下一节把它量到底）。

同一批量按 `walk0/sd` 分档（strike 越大）看结果：

## 6. 决定性检验：把价格按住，dev 还有没有用

用户命题的可证伪读法：**同一价位里，dev 还能不能分开好坏**。
能 ⇒ 它真在选；不能 ⇒ 它的全部作用只是「与价格相关」（ρ(walk, fill) = +0.31 那件事）。

方法：把 `fill` 切成 **0.005 宽的窄桶**，桶内按该量的中位数二分，汇总「高档 − 低档」

⇒ **判读：不足以支撑再加一层 dev 过滤**。这条留档，并在 §10 给出前向判据。

`[0.98,1.01)` 两带**完全没有这个梯度**——同样是薄格，登记不采信。

## 7. 要监控什么：三个读数

| 读数 | 定义 | 含义 | 备注 |
|------|------|------|------|
| `dev(t)` | `sgn·(spot(t) − anchor)` | **入场缓冲 + 现货已走的量**（`rem ≥ 60` 段恒等） | 现货口径，**带水平差** |
| `walk(t)` | `sgn·(twap(t) − anchor)` | **计分板**：结算线此刻值多少，闭市那一刻它就是结果 | 无水平差、平滑 |
| `room(t)` | `sgn·(spot(t) − P(rem))` | **前瞻**：现货从此冻住会赢多少（美元） | `P` 见下 |

其中 `P(rem)` 就是决策 #30 已经落引擎的**「临界价」**（`internal/tail.RequiredPrice`）：

```
rem ≥ 60:  P = anchor
rem < 60:  P = (60·anchor − 已定局那 (60−rem) 秒的价和) / rem
```

三条已实证的性质：

1. **`rem ≥ 60` 时 `room(t) ≡ dev(t)`**（实测 63555 个点，最大偏差 **0.00e+00**）。
   ⇒ 用户那句话在 `rem ≥ 60` 段是**恒等式**：入场后的实时 `dev` 就是「入场缓冲 + 现货走的量」。
2. **`rem < 60` 之后两把尺子分家**：`dev` 把「已经定局的那几秒」当成还能挣回来的账。
   一个真实例子：某窗 `rem=29s`、现货 84526.5、临界价 `P=84515.1` ⇒ `room = −11.4`
   而 `dev = +2.4`（`dev` 说「还赢着」，真话是「冻住就输」）。全部 102704 个 `rem<60`
   的 tick 上 `|room − dev|` 中位 **101.2 美元**、p90 923.8。
3. ⚠️ **`room` 是近似不是口径**：它的「已定局价和」由**逐秒 Binance 现货**估，
   而结算走 Chainlink。实测这个水平差（末 60 秒现货均价 − 结算值，3802 窗）
   **中位 +31.5 美元**（p25 +17.9 / p75 +53.1）。
   后果：拿末点的 `room` 符号去猜输赢，1954 笔里错 **56 笔（3%）**——**错的恰恰是贴线窗**：
   65 个输单里有 **42 个** 的 `room` 全程为正（它们是「差几美元」输的，被 +31.5 美元的水平差
   盖过去了）。这个洞在 Go 侧 `RequiredPrice` 的注释里已存档。

**赢/输两组在各读数上的暴露**（持仓期间该读数曾为负的比例 / 为负的时长占比）：

| 组 | 读数 | 曾为负 | 时长中位 | 时长均值 |
|----|------|--------|----------|----------|
| 赢（1894） | `room(t)` | 23 (1.2%) | 0.0% | 0.3% |
| 赢 | `dev(t)` | 43 (2.3%) | 0.0% | 0.4% |
| 赢 | **`walk(t)`** | 129/1892 (**6.8%**) | 0.0% | 2.7% |

**`walk` 是唯一能把输单挑出来的那把尺子**（87.7% vs 6.8%，领先 13 倍）——它无水平差、
平滑、而且闭市那一刻它就是结果。现货口径的两个读数都因为水平差而漏掉了一半输单。

其余路径统计（均为中位数，美元）：入场后 `min dev(t)` 赢 **76.2** / 输 **3.0**；
`min walk(t)` 赢 **+48.3** / 输 **−7.8**；
**缓冲消耗率** `min dev(t)/dev0` 赢 **0.89**（p10 0.40，24.2% 的赢单曾吃穿缓冲）/
输 **0.04**（p10 −0.90）。

**落地规格**（纯旁路，不参与判定——与持仓监察决策 #24 同一性质，实施前需用户点头）：

- `tailhold_*` 行加三列 `dev` / `walk` / `room`（外加各自的持仓期最小值），
  以及 σ 归一版本（除以 `sd`）供跨窗比较；
- 页面曲线加第 6 条 `spot − P(rem)`（`P` 已在画，相减即可，**零新公式**）。

## 8. 出场规则：又否一次

「看着它跌就卖掉」在持仓路径上只有两种写法，两种都否（基线 = 持有到期
n=1959 / +12.29U @2U）：

| 触发量 | 阈值 | 触发笔数 | 冻结 | Δ P&L | 95% 配对区间 | 触发时 rem | 出场 bid | 救输/杀赢 |
|--------|------|----------|------|-------|--------------|-----------|----------|-----------|
| `dev(t)` | < 0 美元 | 68 | 7 | **+2.77U** | **[−20.41,+1.30]** | 47 | 0.775 | 25 / **43** |
| `dev(t)` | < −20 | 35 | 9 | +1.28U | [−19.99,−2.95] | 44 | 0.700 | 15 / 20 |
| `dev(t)` | < −40 | 20 | 7 | −1.45U | [−17.98,−9.92] | 41 | 0.570 | 9 / 11 |
| `walk(t)` | < 0 美元 | 153 | 33 | **−8.13U** | **[−32.85,−6.85]** | 52 | 0.910 | 24 / **129** |
| `walk(t)` | < −20 | 29 | 6 | −3.64U | [−21.13,−10.41] | 52 | 0.910 | 6 / 23 |
| `walk(t)` | < −40 | 5 | 4 | −0.46U | [−13.47,−12.18] | 52 | 0.930 | 1 / 4 |

**为什么必然如此**：在 0.99 的价位上赢一笔只赚 `(1−0.99)/0.99 ≈ 1%`，而输一笔亏 100%
⇒ 盈亏比 99:1 ⇒ 止损要在 0.99 附近**几乎不误杀**才划算；而 `walk(t) < 0` 是市场早已
报出的状态（触发时出场 bid 中位 **0.910**），你卖出的是「已经定价完的坏消息」。

这与决策 #24（dev 双腿）、#39（下穿停留时长 / 穿越次数）、速度投影止损（10-03）
**是同一族、同一个结论**：市场报得比你能反应的速度快。**不得再提**（除非先有新机制）。

## 10. 结论与建议

### 对用户命题的裁决（逐条）

| 用户的说法 | 裁决 | 依据 |
|------------|------|------|
| 「dev/basis/walk/sd 预测不了未来」 | ✅ **成立** | §4：`corr(walk0/sd, Δwalk/sd) = −0.007` |
| 「真正决定成败的是持仓后 spot 往不利方向走多少」 | ✅ **成立且是恒等式** | §3：余量 `= dev0 + Δ`，赢 ⟺ `Δ > −dev0` |
| 「dev 大 walk 大 = 能承受的逆向移动更多」 | ✅ **成立且是恒等式** | §2 + §7：`rem ≥ 60` 时 `room(t) ≡ dev(t)`，偏差 0 |
| 「这些量是拟合出来的、基本无意义」 | ⚖️ **一半成立** | §6：把价格按住后 `dev0` 在 `data/events` 上仍有 **+2.0pp / +44.24U** 的增量（区间不含零、九种参数组合全稳、10/15 天为正），但在 `data/btc` 上**反号**（−0.6pp / −14.05U）⇒ **不是定律**；且两个分量各自都分不开，形状更像噪声 |
| 「价格」没被提到，但它是真正的决定量 | ✅ **`corr(市场价, 结果) = +0.892`** | §5：四张校准图基本是平的，价格 ≈ 胜率 |

### 建议

1. **不要再往判定链里加 dev / walk / basis / sd 系的过滤条件**（§6 反号 + 分量形状像噪声；
   加上已否家族 24 特征 / τ-k 网格 / 检查点网格 / 速度投影 / σ 梯度）。
2. **要监控就监控 `walk(t)` 与 `room(t)`**（§7）：这两个是**风险读数**，不是入场规则。
   可以落成纯旁路（`tailhold_*` 加列 + 曲线加线），**但必须由用户点头**，
   且不得进入任何判定 / P&L / 熔断路径。
3. **真正该盯的是 §9 那条边际衰减**：`data/btc` +1.695% → `data/events` +0.314%
   （扣费后 +1.434% → **+0.058%**）。这不是过滤条件的问题，是**这笔生意最近不赚钱**了。
   建议下一步就做这件事的取证（分价格带 / 分段的边际随时间变化，含费），
   而不是继续调参。
4. **`data/events` 上那条 dev 增量（+44.24U）登记为待复验**，不进引擎。
   前向判据（先写死再跑，样本 = 此后 ≥14 个完整日的新信号）：
   - ① 同一套窄价桶（0.005 宽）内二分，高档边际 − 低档边际的**日级配对 95% 下界 > 0**；
   - ② 净 Δ P&L ≥ **+10U / 14 天 @2U**；
   - ③ 两个分量（`walk0` / `basis0`）中**至少一个**单独也能同号分开。
   三条同时满足才谈落地；任一不满足 ⇒ 撤回并归档。

### 与已否家族的关系（说清边界，避免重提）

- §6 检验的是「**再加一层 dev 过滤**」，与已否家族不冲突（那些是换阈值 / 换检查点 /
  换条件），但它**没有通过**才没落引擎。
- §8 的出场腿与决策 #24 / #39 / 速度投影（10-03）**同族同结论**，**不得再提**。
- §5 的校准图与 GBM 族（10-01）**互为印证**：那族否掉的根因是
  「模型 AUC 0.8789 < 市价 0.8807」，这里从另一个方向得到同一句话——**价格已经把
  可预测的部分吃干净了**。
