## §1 为什么这一条必须用实盘验证（用户口径）

- 回测的前提是「快照瞬间即成交」，实盘是「GTC 挂单等成交」——**不是同一个估计量**
  （CLAUDE.md 项目概述里已记：0.99 的窗实盘近半不成交）。
- 止损要回答的是「**持有中的这批仓位**崩到 0.30 以下时卖出去划不划算」——而「崩」这件事
  在两个宇宙里的分层完全不同：回测里 0.30 之下有大量**假摔**（杀赢 26/112 = 23.2%），
  实盘里几乎全是**真崩**（2/25 = 8.0%）。原因就是成交的逆向选择。
- 用户判断（原话见文首）：大部分参数是用回测调出来的，回测里它们（连同止损）都可能
  带着过拟合的偏差；**止损保护的是实盘那个分布**，所以按实盘验证。
- ⇒ 本条的一切数字以 `data/tail-live/`（服务器真实成交）为准；回测数字仅作对照（§6）。

**口径**（与 `docs/` 系列同一套）：

- 触发 = 逐 tick 扫 hold 行：`rem > 0` ∧ `book_latency_ms ≤ 300`（`StopArmed` 同口径）

- Δ = Σ(反事实 − 行上真实 PnL)；区间 = **日级配对** bootstrap（`boot_delta` 同实现,
  n=2000 seed=44，与 23/38/41/42 一致——只能按「同一批日子重采样」读）。
- **§0 自检**：644 笔（赢 613/输 31，胜率 95.19%）/ 468 笔可评估 / 基线 +15.67U——
  任何一条对不上 dashboard，就是读错了数据。

## §5 为什么是纯价格腿，而不是原文档的 `bid ∧ dev` 双腿

实盘对照（同集合、同出场口径）：

| 口径 | 触发 | 输单命中 | 误杀 | Δ | 出场价中位 |
|------|------|----------|------|----|-----------|
| **纯价格腿 `bid<0.30`** | **25** | **23/23** | 2 | **+45.51U** | **0.260** |
| `bid<0.30 ∧ dev<−20`（原文档口径） | 9 | 9/23 | 0 | +12.60U | 0.101 |
| `bid<0.30 ∧ dev<0` | 15 | 15/23 | 0 | +28.98U | 0.210 |
| `bid<0.30 ∧ dev<−50` | 4 | 4/23 | 0 | +3.31U | 0.085 |

**机制**：`dev = sgn·(spot − anchor)` 是**结算线**的位移；触发秒它的中位是
**+14.82 美元**、**76% ≥ 0**——报价已经塌到 0.30 之下，结算线还没动。
dev 腿 = 等确认，而确认到的时候报价已经走远（出场价从 0.260 掉到 0.101，
救回的钱只剩四分之一）——与 memory [[tail-stoploss-is-feed-lag-timing-2026-09-29]]
同源：**优势在报价与结算线的时差里，dev 确认就是把这个时差等没**。

**阈值扫描**（看形状，不选参数；0.30 是用户决定值不是 argmax）：

| X | 0.15 | 0.20 | 0.25 | **0.30** | 0.35 | 0.40 | 0.50 |
|---|------|------|------|----------|------|------|------|
| 触发 | 24 | 24 | 24 | **25** | 25 | 28 | 31 |
| Δ | +18.80 | +30.12 | +43.86 | **+45.51** | +61.50 | +50.56 | +55.46 |

全格为正；0.35 更高，但 25 个触发的样本上**不拿扫描极值当依据**——按用户决定值 0.30。

## §7 落地形态（决策 #34 实现面）

**纯函数**（`internal/tail/stop.go`，判定与执行两侧的唯一口径）：

- `StopTrigger(cfg, bid)` = `enabled ∧ bid > 0 ∧ bid < 0.30`——严格小于；
  **bid == 0 不是触发**（整侧撤空 = 卖不掉，触发它只会产出注定被拒的卖单，决策 #21）；
- `StopArmed(maxLatMs, tick)` = `rem > 0 ∧ BookLatMs ≤ 300`——**不要求 spot/anchor**
  （止损不看结算线；这是它与判定路径半有效 tick 口径的唯一差异，有意为之）；
- `HoldBidOf(side, tick)` = 押 yes 取 `UpBid` / 押 no 取 `DownBid`（与持仓监察同源）；
- `MinSellShares = 5.0`（CLOB 最小单量，买卖同一约束）。

**编排**（`internal/tail/exec_state.go` `StopSell`，四条终局）：

| 卖出结果 | 动作 |
|----------|------|
| `filled` / `partial` | `Recorder.RecordExit` 立即落盘（加权平均累计）→ 剩余若仍 < 0.30，下一 tick 自然再卖 |
| `unfilled`（FAK 吃不到 / 429 / "no orders found to match"） | **不落盘不冻结**，下一 tick 重试（调用方日志节流 1/15） |
| `rejected`（含**结果未知**前缀）| **冻结**: 写一次 `exit_note`, 本窗不再尝试——未知结果绝不重试（可能已成交，重试 = 卖两次） |
| live 残仓 < 5 股 | 冻结（反复尝试只会被交易所拒；写 note 交人工。paper 不套这条——默认 stake 下整仓不足 5 股，套用会让纸面止损永远不成交） |

落盘失败（磁盘错）同样冻结——交易所那笔可能已成交，宁可留 note。**绝不臆造成交**。

**主循环接线**（`cmd/tail/main.go`）：仓位两处开闸——① 决策即成交（`HasPosition()`）；
② 挂单**窗内定稿**（`fillFinalCh`，须比对 `conditionID` 防上一窗陈条）。此后每 tick
检查一次，直到闭市（`rem == 0` 由 `StopArmed` 拦下）。

**记录**（`internal/tail/recorder.go`）：新增 `exit_shares` / `exit_price`（加权平均）/
`exit_rem`（**只记首次**，页面显示「止损发生于 rem=x」）/ `exit_ts` / `exit_note`；
结算 `recomputePnL`：`pnl = exit_shares·exit_price − cost (+ 剩余股数 若赢)`——
**止損行照常结算**（`won` 照官方回填），钱按实际落袋算。

**执行器**：`flip.SellExecutor` 接口（新，`internal/flip/sell.go`）+ `PaperSellExecutor`
（按限价成交，纸面同跑——影子观测）；`trading.LiveSellExecutor`（FAK，**单次 POST
即终态**，撤单不需要——FAK 余量自动撤）。

**配置**（2 键，见 §10）；**页面**：信号表**状态列**显示止损标签（「止损卖出」/
「止损冻结」）+ 悬停明细（卖出股数/均价/rem/说明），结果列只放官方赢/输——用户
2026-10-03 修正口径（原定为结果列，当日复核后移到状态列）。

**parity 免疫**：判定链一字未动；止损是**旁路**（不进 Engine 状态机、不进 oracle 红线）。
pin 不变：6704 / 2074 / 3640 / 3 / 250 / 24 / 97.830280% / +70.314372U。

## §8 风险与已知偏差

1. **样本薄**：8 天 25 次触发；Δ 的 54% 来自两天（09-28 +14.11 / 09-30 +10.40）；
   撑起结论的是 23 笔输单 + 2 笔误杀——误杀是真实存在的（8%），不是零成本保险。
2. **出场价是「快照 bid 全额成交」口径**（与回测同源的假设）。§4 证明了当时簿上有对手方
   （bid5 最小 33 股），但 FAK 的实际成交价可能更差——**实际值只能等实盘**（§9 ②③）。
3. 🔴 **CTF ERC1155 卖出授权未验证**（本条最要紧的执行面风险）：买 = USDC ERC20
   allowance，卖 = Conditional Tokens 的 `setApprovalForAll`，**两回事**。
   SDK v0.7.2 只有 ERC20 `Approve`（relayer 包），**没有 1155 授权方法**；本仓库
   从未用过 relayer。若授权未设：卖单被拒 ⇒ 冻结 + `exit_note`（钱不会错，但**止损
   静默失效**）⇒ 上线前必须验证（§10）。
4. **冻结语义保守**：拒单/未知一旦出现就本窗放弃。若拒单原因是系统性的
   （正是第 3 条），表现是「止损看起来没在工作」——`exit_note` 非空的行 = 人工清单。
5. **live stake 与最小单量交互**：10U/0.99 ≈ 10.1 股 ≥ 5 —— 现行 live 档没问题；
   若未来把 stake 降到 < ~5U，触发时残仓 < 5 股会**冻结**（卖不出去）。
6. **现行宇宙的增量略小**：25 次触发里有 2 次（t60@0.81 / 监听@0.82）在 #33 地板之后
   根本不会建仓 ⇒ 地板之后的等价增量 ≈ **+41.09U / 23 次**（前向读数按 §9 在新样本上重取）。
7. **触发集中在 t150（20/25）**：T=150 段是入场闸（#29）放行后的「结算线已走 43 美元+」
   那批——它们崩起来也是真崩；与「闸与止损是替代品」（#39 §0b：闸后止损回测增量
   从 +9.54U 缩到 +4.99U）并不矛盾：替代关系在回测宇宙里成立，实盘宇宙里止损的
   增量仍然很大（这正是两宇宙分层不同的又一例证）。

## §9 前向判据（先写死，再跑）

**触发条件**（先到为准）：**≥ 30 次止损触发** 或 **≥ 14 个完整日**（自 2026-10-03 起）。

| # | 判据 | 现值（实盘回看） |
|---|------|------------------|
| ① | 成交面：触发中「未冻结」占比 ≥ 85% | 25/25（未冻结） |
| ② | 成交面：实际成交价中位 ≥ 快照 bid − 0.03；请求股数全额成交占比 ≥ 90% | 快照口径无法先验，待实盘 |
| ③ | 残值：实际成交价中位 ≥ **0.15** | 0.260 |
| ④ | 误杀率（触发但最终赢）≤ **15%** | 8.0% |
| ⑤ | 日级配对 Δ 的 95% **下界 > 0**（@10U/注） | [+22.62, +70.44] |

①~⑤ 全满足 ⇒ 继续留用；②/③ 不满足 ⇒ **撤回**（成交面不成立，出场价再算都是纸面）；
④ 或 ⑤ 不满足 ⇒ 撤回或把阈值降到 0.20 重议（用户决定）。任一撤回都**保留记录行**。
