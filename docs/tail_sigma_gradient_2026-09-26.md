## §0 口径与坐标（先读这一段，后面所有符号都在这里定义）

| 符号 | 定义 | 单位 |
|------|------|------|
| `anchor` | 该窗的 TWAP-60 开盘值 = 边界那一秒的 Chainlink 推送（决策 #15） | 美元 |
| `dev` | `sgn·(spot − anchor)`；`sgn` = 押 yes 时 +1 / 押 no 时 −1。正 = 朝**押注方向**走的位移 | 美元 |
| `hist_bps` | 前 ≤18 个已完窗口 `\|close−open\|/open` 的均值（需 ≥3 窗，决策 #13） | 基点（1e-4） |
| `sd` | `hist_bps × anchor / 1e4` = **该窗 1σ 折成美元** | 美元 |
| `z` | `dev / sd` = 位移等于几个 σ | 无量纲 |
| `hot` | 判定 tick 热门侧**有效价**（ask 优先、bid 兜底，决策 #22） | 价格（0~1） |
| `fill` | 成交价假设 = `hot`（回测口径：触发瞬间按限价成交、无滑点）；`shares = 2U / fill` | 价格 |
| `hot_src` | 有效价来自 `ask` 还是 `bid` | 枚举 |

**读 P&L 的唯一正确姿势：盈亏平衡胜率 ≡ 成交价 `fill`。**
买在 `p` 时，赢一笔只赚 `2·(1−p)/p` 美元、输一笔亏满 2U ⇒ `胜率 = p` 时 EV = 0。
所以「fill 0.98 ⇒ 必须赢 98% 才不亏」，全表到处出现的「平衡线」就是这个数。

## §2 病根：现行规则的 `dev_min(sd)` 在 sd=40 处有断点

现行 ⑤（T=60 段与监听段 ②）：

```
⑤ = hot ≥ 0.80 ∧ ( dev ≥ 63  ∨  ( sd ≥ 40 ∧ dev ≥ sd ) )
② = hot ≥ 0.80 ∧   dev ≥ 63
```

把它换算成「要求几个 σ」：

| sd（美元） | 15 | 20 | **25** | 30 | 39.9 | 40 | 63 | 80 | 120 |
|-----------|----|----|----|----|------|----|----|----|-----|
| 现行 dev_min | 63 | 63 | 63 | 63 | 63 | 40 | 63 | 63 | 63 |
| 现行要求 z | 4.20σ | 3.15σ | **2.52σ** | 2.10σ | 1.58σ | 1.00σ | 1.00σ | 0.79σ | 0.53σ |

即那条「连续段 `dev ≥ sd`」**只覆盖 sd ∈ [40, 63)**，两侧都跳回固定 63 美元：

- `sd < 40` ⇒ 门槛不降反升，**σ 越小越苛刻**（σ=25 时要 2.52σ）★断点在 40
- `sd ≥ 63` ⇒ 63 美元封顶，σ 越大越宽松（σ=120 时只要 0.53σ）

低波动期正好落在最苛刻的那一侧——这就是信号消失的机制。

## §3 方法：候选必须重跑三段判定链

**为什么不能在既有信号池上打标签**：放宽 ⑤ 会改变「哪个 tick 首次达标」。
一个原本在 `rem≤60` 才达标的窗，放宽后可能在 `rem=150` 就达标——入场价、`dev`、
结算路径全变了，还会连带改变后续监听段的触发。正确做法是**改谓词、重跑整条链**。

做法（脚本里就是这段）：直接替换 oracle `23_tail_integrated.py` 的 `r5` 谓词，然后

## §7 风险与已知局限（处置前请逐条读）

### 7.0 最硬的一条：「保证胜率」没有通过（§6.1）

**每一档价格闸的胜率下界都低于它自己的平衡线。** 最接近的 `hot≥0.97` 还差 0.74pp。
⇒ 就字面意义而言，**这次没有找到「在保证胜率的前提下」成立的梯度阈值**；
找到的是「两个样本上都为正、且配对区间不含 0，但绝对胜率仍不显著」的形态。

### 7.1 超额只有 +2.1 笔，实盘那半边只有 +0.2 笔

买在 0.984 意味着赢一笔只赚 `2·(1−0.984)/0.984 = +0.033U`，输一笔亏满 `−2U`
——**每输一笔要 62 个赢家才补得回来**。合并边际族 196 笔：

```
赢 195 笔，平衡线要求 192.9 笔  ⇒  超额 +2.1 笔
```

拆开看实盘那 13 笔：赢 13、平衡线要求 12.8 ⇒ **超额 +0.2 笔**。

**敏感性：实盘边际族翻转任意一笔为输，该族 P&L 从 +0.41U 掉到 −1.62U 量级。**
⇒ 这条规则在实盘上**目前等于没有证据**。

### 7.2 实盘边际族的胜负**全部是推导来的**

13/13 都是 `tailwin` 的 `(anchor, close)` 推导（引擎当时从未下单 ⇒ 没有官方 `won`
可读）。决策 #19 记的「engine 的 close 仍是到达口径」在这批数据里已出现过 1 例
贴线不一致（255 对里 1 对，差 0.696 美元 ≈ 0.08 基点）。推导方向若有一例翻错，
结论如 §7.1 所述直接翻负。

### 7.3 两个阈值都**不可辨识**，禁止再调

- **价格闸 `0.95`**：回测里闸越松越好——**无闸（+59.85U）高于 0.90~0.99 网格上的
  任何一点**，argmax 贴网格下边缘（0.91），`hot≥0.95` 只排第 7/10。曲线在
  0.90~0.99 上近乎平坦（+52.8 ~ +58.8U，±1U 噪声）。
  ⇒ **选 0.95 的唯一依据是实盘子样本**（纯梯度实盘 −3.05U → 加闸 +0.41U），
  代价是明确放弃约 **5.2U 回测 P&L**（+59.85 → +54.64）。这是取舍，不是优化。
  `0.97` 变体同理：它在两样本上都是「去掉一个负档」（§5.3），但同样贴网格下边缘、
  同样过不了 §6.1 的检验；两个值之间的选择**没有统计依据**。
- **`1σ` 与 `25 美元`**：提高 z 单调变差（§4 事实 2），说明 σ 倍数没有内部最优；
  `floor=25` 只是防「σ 极小时门槛贴近 0」的地板。
- 这与 σ 腿的 `40`（决策 #17：2000 次重采样里一次没成为 argmax）是同款处境——
  **纸面登记，不许据回测调参**。

### 7.4 实盘监听段无法复核

监听段（②，`hot ≥ 0.80 ∧ dev ≥ 63`）**不落被拒的逐 tick 记录** ⇒ 实盘无法重跑。
本次只改 ⑤、②一字不动，监听段与基线逐窗相同，所以实盘子样本仍成立；
**但将来若要动 ②，实盘将没有对应的复核手段**（回测可以，实盘不行）。

### 7.5 样本量与外部效度

- 回测 14 天 + 实盘 3 天 = **17 天**、合并边际族 196 笔；实盘只覆盖 3 天、
  其中 09-26 只跑了不到半天。
- 三个 σ 塌缩事件（08-29/30、09-26）都落在样本内，**但没有一次是 OOS 的**。
- 参数纪律提醒：本族的「恢复量」集中在低σ日，与本策略在低σ环境的**未知行为**
  同源——恢复的是**样本量**，不是被验证过的收益。

### 7.6 交易所下限仍然横在那里（与本次改动无关）

决策 #21 ②：`minimum_order_size = 5 股`，而 `tail.stake=2U` 在 ≥0.80 只有 2.0~2.5 股
⇒ **低于交易所下限**。本推荐族把入场价推到 0.95+ ⇒ 2U 只有 **2.1 股**，问题更突出。
tail 上 live 前必须先解决 stake（用户决定）。
